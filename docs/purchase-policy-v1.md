# v1 구매 인정과 정답 계약

현재 v4 구현은 아래 상태·정답 계약에 [테스트 계정·충전 상품·샘플·사은품 제외](evidence/preprocessing-applied-v4.md)를 우선 적용한다.

2026-09-16. 첫 실험을 진행하기 위한 구현 기준이다. 반품의 실제 소비량이나 재입고량을 확정한 규칙은 아니다. 원본은 보존하며 애매한 사례는 아래 기준으로 보류한다.

## 예측 대상

고객 × 상품 코드별 **다음 정상 재구매 날짜와 그날의 주문 개수**를 예측한다. 다른 상품만 산 주문은 이 상품의 0개 정답이 아니다. 중량으로 환산하지 않으며 옵션 선택은 앱이 담당한다. 예측 날짜가 되면 앱이 예측 개수를 장바구니에 제안한다. 수량 성능이 우선이고 날짜 오차도 반드시 평가한다.

날짜는 주문 시각 `ordered_at`의 한국 시간 날짜인 `ordered_on`을 사용한다. 완료·갱신·추출 날짜로 바꾸지 않는다. 같은 고객·상품의 같은 날 정상 주문은 일 단위 이벤트로 합산하고 주문별 연결을 보존한다. 따라서 다음 이벤트는 반드시 더 늦은 날짜다. 이는 한 주문서의 수량이 아니라 다음 구매일의 총 주문 개수를 목표로 하는 v1 설계 선택이다. 하루 여러 번 장바구니를 채우는 동작은 v1 범위 밖이다.

## 행 사용 기준

판단 단위는 `(order_id, product_id)`다. 상품 항목 코드가 달라도 같은 주문의 같은 상품은 함께 확인한다. 다른 상품에는 보류를 전파하지 않는다. 항목 코드가 서로 다른 상품을 가리키는 등 식별자 충돌은 자동 처리하지 않고 실행을 실패시킨다.

입력은 주문별 최신 버전을 선택해 추출·고정한 `order-items-v2.csv`다. 상세 고유 키는 `(order_id, order_section_item_no)`이며 같은 키가 두 번 나오면 값이 같더라도 실행을 실패시킨다. 상태·수량이 충돌한 중복에서 임의로 하나를 고르지 않는다. 최신 버전 선택은 추출 단계의 책임이고 이번 판정은 상태 변경 이력을 복원하지 않는다.

| 상태 구성 | 결정 | 수량 처리 |
|---|---|---|
| PURCHASE_CONFIRMATION / SHIPPING_COMPLETE만 존재 | 정상 구매로 포함 | 고유 상세 행의 양의 개수를 합산 |
| CANCEL_COMPLETE만 존재 | 제외 | 정상 구매 이벤트를 만들지 않음; 0개 학습 예제로 만들지 않음 |
| 완료와 취소가 함께 존재 | 해당 주문·상품 보류 | 완료분만 임의 선택하거나 취소분을 빼지 않음 |
| RETURN_COMPLETE 또는 교환 상태 포함 | 해당 주문·상품 보류 | 반품·교환을 새 구매 또는 음수 수요로 만들지 않음 |
| PRODUCT_PREPARATION / SHIPPING_READY / SHIPPING 포함 | 해당 주문·상품 보류 | 완료되기 전에는 정답으로 사용하지 않음 |
| 미등록 상태 | 해당 주문·상품 보류 | 새 상태를 정상 구매로 자동 승인하지 않음 |

여러 보류 사유가 겹치면 미등록 상태 → 반품·교환 → 진행 중 → 부분 취소 순으로 대표 사유를 기록한다. 원본 상태는 모두 남긴다. 포함은 현재 스냅샷 기준 구매 인정이며 과거 어느 날 학습 가능했다는 뜻은 아니다.

## 재구매 연결과 관측 종료

4단계 구현은 다음 규칙을 따른다.

1. 포함된 행을 고객·상품·한국 날짜로 합산한다. 그 날짜에 같은 고객·상품의 보류 주문이 하나라도 있으면 해당 날짜 전체를 보류하며 정상 행의 수량도 그날 정답에 쓰지 않는다. 취소만 있는 주문은 장벽이 아니다.
2. 보류 이벤트는 이력에 장벽으로 남긴다. 정상 구매 A → 보류 B → 정상 구매 C → 정상 구매 D에서 A의 다음 구매를 C로 붙이지 않는다. A의 다음 날짜·수량 정답은 `blocked_by_hold`로 남긴다. C → D는 유효한 새 연결이다. 취소만 있는 날짜는 이벤트를 만들지 않는다.
3. 보류로 끊기지 않은 관측 이벤트 순서에서 인접한 정상 구매일 A → B의 정답은 B의 날짜, B의 개수, 두 날짜 차이다. 달력상 연속된 날짜일 필요는 없다. 첫 관측 구매는 과거 간격이 없는 이력으로 보존한다. 보류 이전 기록을 사용하더라도 최근 간격·수량 피처의 연속 구간은 장벽에서 다시 시작한다.
4. 마지막 정상 구매 뒤 다음 구매가 없으면 `right_censored`로 보존한다. 0개나 무한 일수로 채우지 않는다. 날짜·수량 회귀의 정답이 있는 쌍과, 미관측·보류·이력 부족 대상을 별도로 집계한다.
5. 주문 관측 범위는 2026-04-09~2026-09-15다. 수집 끝 날짜의 완전성은 별도 확인 전까지 보장하지 않는다. 날짜별 파일 생성과 회귀 예제 생성은 4단계이며 이번 단계에서는 행 사용 판정만 생성한다.

## 시점 정보와 평가 제한

현재 CSV는 최신 상태 스냅샷이며 상태 변경 이력이 없다. `ordered_at`은 주문 시각, `source_updated_at`은 주문 레코드 갱신 시각, `extracted_at`은 추출 시각이다. 어느 것도 구매 확정·반품 완료의 실제 시각으로 대신하지 않는다.

현재 판정을 확실히 관측한 시각은 각 행의 `extracted_at`으로 기록한다. 일별 이벤트의 관측 시각은 구성 행의 최댓값을 쓴다. 과거 학습 경계에서 이용 가능했다는 증거가 없으면 엄격한 과거 시점 재현 평가에는 넣지 않는다. 5단계에서 상태 변경 이력 또는 당시 스냅샷을 확보할 수 있는지 확인한다. 확보 전 최신 상태로 정제한 과거 실험을 할 경우 **사후 정제 탐색 실험**으로 명시하고 운영 성능이나 가드레일 통과로 발표하지 않는다. 이 제한을 임의의 7일·30일 지연으로 해결했다고 간주하지 않는다.

회귀 오차는 다음 정상 구매를 관측한 대상에 한정된다. 전체 대상 수, 정답 관측 수, 보류 수, 미관측 수를 함께 보고한다. 실제 재고 소진 시점은 현재 주문 데이터로 확인할 수 없으므로 재구매 날짜를 소진일의 실측값이라고 부르지 않는다.

## 산출물과 다음 단계

`python3 -m scripts.apply_training_policy data/order-items-v2.csv --output-dir data/purchase-policy-v1`

출력 `rows.csv`는 원본 모든 열과 행을 그대로 유지하며 행 번호, 정책 버전, 포함/제외/보류 사유, 포함 가능한 개수, 장벽 여부를 추가한다. 제외·보류의 `eligible_quantity`는 빈 값이며 0개 정답이 아니다. `training_ready=false`는 아직 구매일 이벤트·라벨·시점 검증이 끝나지 않았다는 뜻이다. 기존 출력은 덮어쓰지 않는다. 보고서의 상태별 원본 수량 합은 대사용이며 수요 통계가 아니다.

3단계 완료 조건은 규칙 고정, 모든 원본 행의 판정·수량 대사, 예외 테스트 통과다. 4단계에서 이 계약대로 구매일 이벤트·연결표·정답 쌍과 미관측 목록을 생성했다. [구현·검증 결과](evidence/purchase-events-review.md)를 참고한다. 실제 학습과 앱 연결은 이후 단계다.
