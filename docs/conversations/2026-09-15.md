시기 예측 성능:  가장 근본적인 결과값이며,. 고객별 다음 발주 시기의 예측을 얼마나 가깝게 예측하였는지를 설정한다.
고객군의 구별: 고객 마다 재구매하는 기간이 다르다. 그렇기에 고객군을 나눠 예측값을 개별적으로 산출하여 예측 유형의 일종의 평탄화가 필요할 수 있다.
상품군의 구별: 마찬가지로 고객들을 인기 재고부터 그보다 떨어지는 비교적 비인기 재고를 가지고 있다 그러한 경우에 상품군 또한 예측값을 개별적으로 산출하여 평탄화를 이룬다.
수량 예측 성능: 고객별 상품별 다음 발주 주기에서 얼마만큼의 수량이 필요할 것인가를 세분화한 예측 지표의 한 개체로 설정할 수 있다.


이 4가지를 토대로 저희들은 챔피언 모델을 설정해볼 수 있습니다.

핵심성과는 3가지 분석 지표를 종합하여 결정하는데, 이는 고객군 및 상품군 간  성능편차, 시기 예측 성능, 수량 예측 성능으로 설정해볼 수 있습니다.
그리고 이 세가지 지표를 토대로 3가지를 각각 X, Y, ,Z의 좌표를 가지고서 3차원 성능 공간에 표시 해보겠습니다. 다만 이들은 모두 단위가 다르기 때문에 단순하게 원점과 가까운 모델을 고르도록 단순화 시키려고 한다면 각 지표를 공통 기준으로 환산하는 정규화가 필요하다고 생각했습니다.


지피티에게 정규화된 3가지 지표를 계산한 3차원 그래프에서 이상적인 챔피언 모델이 있어야 할 곳을 만들어보았습니다. (2번째 이미지) 하지만 예시일뿐, 가장 이상적인것은 원점에 가까워야합니다.

따라서 챔피언 모델을 붙여넣은 이미지와 같은 예시의 계산식을 사용한다고 했을 때, 각 모델의 세부지표는 정규화된 1이라고 하는 수치에 따라 0.2 즉,  최소한 20%의 오차율을 보일 때부터 성능이 나온다라고 말을 할 수 있을 것 같습니다.

예를 들어보겠습니다.

| 그룹 | 예측 오차 |
| ----- | ----: |
| 고객군 A | 10% |
| 고객군 B | 12% |
| 고객군 C | 11% |
| 고객군 D | 35% |

이러한 지표가 있다고 했을 때, 전체 평균은 괜찮아 보여도 D에서는 모델이 망가지고 있습니다. 그래서 간단하게 처음에는 성능 편차 = 최대 그룹 오차율 - 최소 그룹 오차율로 둡니다. 위 사례를 예시로 들면 35%−10%=25%
즉 편차가 클수록 특정 고객이나 상품에 모델이 편향되어 있다는 의미입니다. 그래서 초기 기준은 고객군·상품군 간 성능 편차 ≤ 10%p 정도로 들 수 있습니다.

그러면 Champion Model 조건이 상당히 명확해집니다.

| 항목 | Champion 후보 기준 |
| ------------ | -------------: |
| 시기 예측 오차율 | *≤ 20%* |
| 수량 예측 오차율 | *≤ 20%* |
| 고객·상품군 성능 편차 | *≤ 10%p* |

라고 했을 때,

| 모델 | 시기 오차 | 수량 오차 | 집단 편차 |
| ----- | ------: | ------: | ------: |
| A | 27% | 18% | 8%p |
| B | 14% | 24% | 7%p |
| C | 18% | 17% | 16%p |
| *D* | *12%* | *15%* | *6%p* |

라면 D만 모든 조건을 통과합니다. D가 champion model이 되는 겁니다. 이런식으로 KR을 개선해 나갈 수 있을 것 같습니다.



따라서 저는 KR을 한가지로 두는 것은 별로 좋지 못한 선택이라고 생각합니다.
KR 최소 조건은
시기 오차 ≤ 20%
 수량 오차 ≤ 20%
 집단 성능 편차 ≤ 10%p

이렇게 두고 조건을 통과한 모델들끼리
3차원 거리 또는 종합 점수로 비교를 하는 것이 좋을 것 같습니다.

따라서 발주예측 알고리즘 신뢰도에 대한 예측지표의 유의미를 정할 KR을 3가지로 나누고, 챔피언 모델의 최소 조건을

시기 오차 ≤ 20%
 수량 오차 ≤ 20%
 집단 성능 편차 ≤ 10%p

로 두는 것이 좋다고 생각이 듭니다!

예를 들어 고객의 평균 재구매 주기가 30일이고, 실제 운영상 ±3일 정도는 괜찮다고 판단한다면:

3/30 x 100 = 10%이고 그러면 이 고객군의 시기 오차 는 10%이하가 실무적으로 의미 있는 기준이 될 수 있습니다. 반대로 ±6일 이라면 20%가 기준이 될겁니다. 그렇기에 정확히 몇 퍼센트다! 이렇게 정하기보다는

| 지표 | 기존 방식 |
| ----------- | ----: |
| 시기 오차율 | 28% |
| 수량 오차율 | 32% |
| 주요 집단 최악 오차 | 40% |

이런 느낌으로 Baseline을 잡아보고, 점차적으로 Champion의 조건을 나누는 것도 좋을 것 같습니다.

그래서 정확한 KR을 잡으려고 한다면 Baseline을 통한 어느정도의 측정하고 다음 KR숫자가 나올 것 같습니다!

## 4. 답변: 초기 검토

제 생각에도 **수량 예측을 주지표로 두고, 시기와 집단별 성능을 통과 조건으로 두는 방향이 더 적절합니다.** 실제로 가장 중요한 것이 “얼마나 필요한지 맞추는 것”이라면, 모델 선정 기준도 그 우선순위를 그대로 반영하면 됩니다.

다만 **평가 기준을 합치는 방법과 CSV 행을 합치는 방법**은 조금 구분해서 설계해야 합니다.

### 1. Champion 선정: 가드레일 통과 후 수량으로 순위 결정

추천하는 구조는 다음과 같습니다.

| 역할 | 지표 | 판단 방법 |
|---|---|---|
| **주지표** | 수량 예측 오차 | 통과한 후보 중 가장 낮은 모델 선택 |
| 가드레일 ① | 시기 예측 오차 | 업무상 허용 범위 이내이며, 기준 모델보다 나쁘지 않을 것 |
| 가드레일 ② | 고객군·상품군별 성능 | 주요 집단 각각에서 해당 집단의 기준 모델보다 나쁘지 않을 것 |

여기서 **baseline은 ‘직전 주기·수량 반복’ 같은 비교용 예측 방식**이고, **20%는 잠정 합격 기준**입니다. 둘은 별도로 관리하는 게 좋습니다.

수량 오차 20%도 초기 목표로 둘 수 있지만, baseline이 이미 12%라면 18%인 모델을 Champion으로 삼아서는 안 됩니다. 반대로 아무도 조건을 못 맞추면 **이번에는 Champion을 선정하지 않고 baseline을 유지**하면 됩니다.

#### 두 가드레일을 하나로 묶는 것은 가능해요

다만 평균이나 가중합으로 묶으면, 한쪽의 좋은 성능이 다른 쪽의 실패를 가릴 수 있습니다.

따라서 처음에는 간단하게:

> **가드레일 통과 = 시기 조건 통과 AND 집단별 조건 통과**

로 두는 것을 추천합니다. 하나의 숫자가 필요하다면 각 지표를 허용 한도로 나눈 뒤 **최댓값이 1 이하**인지 보는 방식이 같은 의미입니다. 이 구조에서는 z-score 정규화가 필요하지 않습니다.

### 2. 집단별 비교는 ‘같은 집단의 baseline’과 해야 합니다

말씀하신 min–max의 한계에 동의합니다. 모든 집단에서 오차가 50%라면 편차는 0이지만 좋은 모델은 아니니까요.

한 가지 더 주의할 점은 **전체 최악 오차끼리만 비교해도 특정 집단의 악화를 놓친다**는 것입니다.

| 집단 | baseline 오차 | 후보 모델 오차 |
|---|---:|---:|
| A | 10% | 25% |
| B | 40% | 30% |

최악 오차는 40%에서 30%로 개선됐지만, A는 크게 나빠졌습니다.

따라서 다음처럼 비교하는 게 의도에 더 맞습니다.

> **각 주요 고객군·상품군에서 후보의 오차 ≤ 그 집단의 baseline 오차**

가능하면 수량과 시기를 각각 확인하고, 집단 간 편차는 보조 보고 지표로 남기면 됩니다. 다만 주문이 몇 건뿐인 집단까지 똑같이 적용하면 판단이 불안정해질 수 있으므로, **평가에 필요한 최소 표본 수를 먼저 정하고 부족한 집단은 별도로 표시**해야 합니다.

### 3. CSV에서 상품별로 여러 행이 있는 것은 정상 구조입니다

실제 파일을 추가로 집계해 보니 다음과 같습니다.

| 항목 | 확인 결과 |
|---|---:|
| 전체 행 | 40,910개 |
| 주문번호 | 14,987개 |
| 고객 코드 | 3,959개 |
| 상품 코드 | 777개 |
| 여러 행으로 구성된 주문 | 8,204개 |
| 주문일 범위 | 2026-04-09 ~ 2026-09-15 |

김철수가 같은 주문에서 복숭아와 포도를 샀다면, 두 행은 **서로 다른 상품 구매 정보를 담고 있는 것**입니다. 단순 중복으로 제거하면 안 됩니다.

대신 목적에 따라 **두 가지 테이블을 만들어 쓰는 방식**이 좋습니다.

| 테이블 | 한 행의 의미 | 용도 |
|---|---|---|
| 주문 이력 | 고객 × 주문번호 | 고객의 구매 간격, 다음 주문 시기 |
| 상품 구매 이력 | 고객 × 주문번호 × 상품 | 상품별 구매 수량, 상품별 재구매 간격 |

이렇게 해야 같은 주문의 상품 5개를 “고객이 다섯 번 주문했다”고 잘못 계산하지 않으면서, 상품별 수량 정보도 보존할 수 있습니다.

**같은 고객·주문번호·상품 코드가 반복되는 조합도 1,857개 있습니다.** 이것은 옵션별 구매인지, 분할 처리인지, 추출 과정의 중복인지 확인한 뒤 합산해야 합니다. 현재 CSV만 보고 무조건 합산하거나 삭제하는 것은 이릅니다.

### 4. 컬럼은 줄이되, 의미 확인에 필요한 정보는 남겨야 합니다

초기 구성은 아래 정도를 제안합니다.

- **핵심:** `member_code`, `order_no`, `주문일`, `prod_no`, `수량`
- **정제용:** `섹션상태`, `상품명`
- **추가 피처 후보:** `가입일`, `사업자여부`, `등급`, 과거 주문 금액
- **모델 입력에서 제외:** `고객명`, `연락처`

특히 이 파일에는 취소·반품 상태가 포함되어 있습니다. 목표가 최초 주문 수량인지, 취소·반품을 반영한 순수요인지에 따라 처리 규칙이 달라집니다.

또한:

- `주문총액`과 `결제금액`이 상품 행마다 반복되어 있다면, 그대로 더하면 중복 집계됩니다.
- 상품명에 `500g / 1kg`처럼 여러 규격이 함께 표시됩니다. **수량 1이 어떤 규격인지** 확인해야 재고 단위의 수량 예측으로 연결할 수 있습니다.
- `등급`이 현재 등급이라면, 과거 예측 시점에도 알 수 있었던 정보인지 확인해야 합니다.

피처는 이 정제를 거친 뒤 **직전 구매 수량, 최근 평균 수량, 마지막 구매 후 경과일, 과거 재구매 간격, 간격의 변동성**부터 만드는 것이 좋겠습니다.

### 5. 가장 먼저 고정해야 할 것은 ‘수량을 언제까지 예측하는가’입니다

다음 두 문제는 서로 다릅니다.

- **다음 주문 때의 수량:** 고객이 다시 주문할 때 상품별로 얼마나 살 것인가?
- **앞으로 일정 기간의 수량:** 다음 7일·30일 동안 고객별·상품별로 얼마나 주문할 것인가?

고객의 다음 구매를 안내하려면 첫 번째가 자연스럽고, 실제 재고 준비가 목적이라면 두 번째가 더 직접적입니다. **수량을 주지표로 둘수록 이 예측 기간을 먼저 정해야 합니다.**

기간별 수량을 예측한다면 구매가 없는 경우도 포함해야 합니다. 실제 구매가 발생한 행만 평가하면, 구매하지 않을 고객에게 과다 예측한 오류를 놓칩니다.

수량 지표의 초기 후보로는 다음을 생각할 수 있습니다.

> **수량 WAPE = 절대 수량 오차의 합 ÷ 실제 수량의 합**

단, 수량 단위가 비교 가능해야 하고, 실제 수량 합계가 0인 집단은 별도 처리가 필요합니다. 대량 구매 집단의 영향이 크므로 집단별 가드레일을 함께 보는 구조와 잘 맞습니다.

### 6. 과적합은 평가 설계부터 막는 게 좋습니다

모델 복잡도는 이후 조정하더라도, **시간 순서에 따른 검증은 처음부터 적용**해야 합니다. 과거 구간으로 학습하고 이후 구간을 예측하는 검증을 반복하며, 군집과 피처도 각 예측 시점 이전 정보로만 만들어야 합니다. 이런 방식이 미래 정보가 평가에 섞이는 것을 막는 기본 원칙입니다. [시계열 교차검증 설명](https://otexts.com/fpp3/tscv.html)

또한 파일 끝부분에서 아직 다음 주문이 관측되지 않은 고객은 “재구매 안 함”으로 바로 판정하면 안 됩니다. 관측 기간이 충분하지 않은 경우를 구분해야 합니다.

**결론적으로 방향에는 동의합니다.** 다음 단계는 **예측 기간·수량 단위 확정 → 주문/상품 이력 정제 → 직전 주기·수량 반복 baseline 측정 → 가드레일 확정 → 수량 성능으로 Champion 선정**이 좋겠습니다. 지금은 모델부터 복잡하게 만들기보다, 이 데이터로 무엇을 정답으로 삼고 어떻게 비교할지 고정하는 것이 가장 중요합니다.

## 14. 답변: 확인 방향

맞아요. 특히 이 CSV에서는 **상품 코드·고객 등급처럼 숫자나 문자열로 된 ‘구분값’을 연속적인 크기로 학습시키지 않는 것**이 중요합니다. XGBoost 공식 문서에서 범주형 처리와 학습·예측 시 코드 일치 조건을 확인해 피처 설계에 반영하겠습니다.

## 15. 답변: 범주형 처리와 문서화 결과

맞아요. **XGBoost는 범주형을 지원하지만, 컬럼의 의미와 학습·예측 때의 처리 방식을 맞춰야 합니다.**

우리 데이터에서는 이렇게 시작하겠습니다.

| 컬럼 | 처리 방향 |
|---|---|
| 상품/SKU 코드 | 범주형 피처 후보. 숫자의 크기로 해석하지 않기 |
| 고객 코드 | 아이템·구매 이력 추적에 유지하고, 첫 모델 입력에서는 제외 |
| 고객 등급 | 과거 시점의 값인지 확인한 뒤 범주형으로 사용 |
| 사업자 여부 | boolean 또는 0/1 |
| 구매 수량·경과일 | 수치형 |

특히 주의할 것은 네 가지입니다.

1. **학습과 예측의 코드 매핑 일치:** 같은 상품이 서로 다른 코드로 바뀌면 안 됩니다.
2. **신규 상품 처리:** 학습에 없던 상품은 별도 표시하고 정해진 대체 예측을 적용해야 합니다.
3. **ID 암기 방지:** 범주형으로 지정해도 고객·상품을 외우는 과적합이 자동으로 해결되지는 않습니다.
4. **저장 후 재현:** 범주형 정보까지 보존하고, 재로딩한 모델의 예측이 같은지 확인해야 합니다.

초기 구현은 `category` dtype, `enable_categorical=True`, `tree_method="hist"`, JSON/UBJSON 저장을 기준으로 잡았습니다. [XGBoost 공식 문서](https://xgboost.readthedocs.io/en/stable/tutorials/categorical.html)
