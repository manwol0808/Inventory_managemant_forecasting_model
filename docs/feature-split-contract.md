# 고객·상품별 과거 입력과 시간 분할

이 문서는 첫 단일 6:2:2 탐색 실험의 계약과 당시 수치다. 현재 다중 구간 비교는 [주기 v2](timing-experiment-v2.md)와 [생존분석](survival-experiment-v1.md)을 따른다. 아래의 미학습·미평가 표시는 첫 입력 생성 시점의 기록이다.

2026-09-16. 고객 × 상품별 구매 이력을 먼저 구성하고 각 이력의 과거 부분으로 다음 날짜·수량을 예측한다. 시간 분할은 이 이력을 학습·평가에 배정하는 기준이며 고객·상품 구분을 대체하지 않는다. 고객·상품별로 개별 6:2:2를 적용하면 전역 모델에 다른 고객의 평가 날짜보다 미래인 주문이 들어갈 수 있어 공통 날짜 경계를 사용한다. 신규 고객 일반화를 검증하는 고객 통째 분리는 별도 실험이다.

현재 구현은 **구매 직후 다음 재구매를 예상하는 탐색용 실험**이다. 점수 대상은 구간 종료 전에 다음 구매까지 관측된 사례에 한정된다. 전체 출발 구매 대비 그 비율은 학습 34.7%, 검증 21.2%, 시험 15.4%다. 수량 오차도 이 선택된 재구매 집단의 오차이며 미구매 고객 전체 성능을 뜻하지 않는다.

## 이번에 고정한 탐색 실험 구간

입력은 `data/purchase-events-v4/`, 설정은 [time-split-v1.json](../config/time-split-v1.json)이다. 날짜는 한국 시간의 **출발 구매일**이며 양 끝을 포함한다.

| 용도 | 출발 구매일 범위 | 일수 | 전체 출발 구매일 | 해당 구간 안에 다음 구매까지 관측한 정답 |
|---|---|---:|---:|---:|
| 학습 | 2026-04-09~2026-07-13 | 96 | 18,975 | 6,579 |
| 검증 | 2026-07-14~2026-08-14 | 32 | 5,633 | 1,196 |
| 최종 시험 | 2026-08-15~2026-09-15 | 32 | 4,865 | 747 |

달력 일수 96:32:32가 6:2:2다. 정답 수를 맞추기 위해 무작위로 섞거나 고객 이력을 잘라 재배치하지 않는다. 6,579/1,196/747개는 사후 정제 탐색용 표본 수다. 엄격한 과거 상태 가용성이 검증된 표본 수는 현재 0개다.

예측 실행 시각은 출발 구매일의 **다음 날 00:00 한국 시간**으로 둔다. 그날 주문을 전부 본 뒤 다음 구매를 예상하는 첫 배치 실험이다. 날짜 모델의 정답 `target_gap_days`는 출발 구매일에서 다음 구매일까지의 달력 일수이며, 예측 실행 시각에서의 잔여 시간과 다르다. 예측 날짜는 출발 구매일 + 예측 간격으로 계산한다. 매일 경과일을 갱신하며 미구매 고객 전체에 재예측하는 운영 흐름은 아직 구현하지 않았다.

다음 구매 정답이 해당 구간 종료일을 넘으면 `crosses_role_boundary`로 보존하고 그 구간의 적합·점수 계산에서는 제외한다. 예를 들어 7월 10일 구매의 다음 주문이 7월 20일이면 7월 13일 마감 학습에 넣지 않는다. 뒤 구간으로 예제를 옮기지도 않는다.

짧은 구간 안에 재구매까지 관측된 표본만 점수를 낼 수 있어 긴 주기 고객은 덜 포함된다. 미관측·경계 초과·보류 건수를 함께 보고하며 이 점수를 전체 고객의 성능이라고 부르지 않는다. 검증 종료 전 다음 구매가 안 보이는 사례를 최종 시험 주문까지 열어 정답으로 채우지 않는다.

## 모델에 넣는 값

원두·시럽 이력은 고객·상품별로 각각 유지한다. 원시 고객 ID는 추적용이며 모델 입력에서 제외한다. 상품 ID는 범주형이다. 보고서의 `feature_columns` 21개만 모델 입력으로 허용한다.

- 해당 고객·상품의 연속 구매일 수, 첫 관측 구매일부터 경과일
- 마지막 수량, 과거 수량 평균, 최근 3회 평균·중앙값·표준편차
- 최근 7일·28일 개수 합계, 과거 구매 간격의 수·마지막 값·평균·중앙값
- 고객의 정상 구매일 수와 구매 상품 수
- 해당 상품의 과거 정상 구매일 이벤트 수·구매 고객 수·평균 개수
- 출발 구매일 요일·월, 상품코드

보류 날짜에서 해당 고객·상품의 연속 구매 이력을 초기화한다. 고객·상품 전체 집계는 그 시점까지 관측된 정상 구매를 누적한다. 현재 구매일도 입력에 포함되며, 같은 날짜의 이벤트는 모두 반영한 후 피처를 계산해 입력 행 순서에 따라 값이 바뀌지 않게 했다. 과거 간격이 없으면 빈 값으로 둔다. 임의의 0일 간격으로 만들지 않는다.

출발 구매일 이후의 날짜·수량·최종 정답 상태·split 이름·snapshot 시각·고객 ID는 모델 입력에 넣지 않는다. 이후 날짜의 구매를 추가해도 이전 출발 구매의 피처 값은 바뀌지 않아야 한다. 현재 버전은 인코더·결측 대체기를 아직 적합하지 않았으며, 다음 단계에서 필요하면 학습 데이터에만 적합한다.

## 조기 종료와 파일

학습 96일 안에서 4월 9일~6월 23일은 `train_core`, 6월 24일~7월 13일은 `early_stop`이다. 각 내부 구간 경계도 다음 구매 정답이 넘지 않도록 한다.

| 파일 | 행 수 | 용도 |
|---|---:|---|
| `train_core.csv` | 4,654 | 조기 종료 반복 수를 고를 때 모델 적합 |
| `early_stop.csv` | 399 | 위 적합의 조기 종료 판단 |
| `train_pool.csv` | 6,579 | 반복 수를 고정한 뒤 검증 시작 전까지 재적합할 학습 전체 |
| `validation.csv` | 1,196 | 후보 성능 비교; 조기 종료에 재사용하지 않음 |
| `final_test.csv` | 747 | 최종 한 구성의 평가를 위해 보관; 점수 미계산 |
| `all-origins-audit.csv` | 29,473 | 모든 정상 출발 구매, 정답 상태, 경계 초과와 가용성 판정 |

`train_pool`은 내부 두 파일보다 크다. 내부 경계 때문에 빠졌지만 학습 전체 종료일까지는 정답이 관측된 예제를 재적합에 사용할 수 있기 때문이다. 모든 파일은 `data/features-splits-v1/`에 있다. 마지막 시험은 논리적으로 잠금 대상으로 표시했으며 파일 접근을 암호화하거나 제한한 것은 아니다.

## 시점 가용성과 실행 상태

주문 날짜 기준 미래 피처·정답 혼입은 검사했지만, 현재 원본은 최신 상태로 과거 주문을 정제한 자료다. 과거에 최종 구매/취소/반품 상태가 알려졌다는 증거는 없다. 현재 피처에 사용된 이벤트의 확인 가능한 snapshot 시각과 정답 snapshot 시각을 검사하면 모든 과거 예측 시점에서 가용성 조건을 통과하지 못한다. 설정을 바꿔 이 시각을 주문일로 소급하지 않는다.

`strict_training_ready=false`, 엄격한 과거 가용성 통과 0개로 기록한다. 이번 산출물은 **사후 정제 탐색 실험용**이다. 운영 성능 검증에는 당시 상태 이력/스냅샷 또는 지금부터 저장하는 예측·후속 주문 로그가 필요하다. 마지막 날짜의 수집 완전성도 아직 확인되지 않았으므로 최종 시험 범위는 운영 검증용으로 확정된 것이 아니다.

누수 점검에서 미래 행 추가 불변성 테스트는 피처 계산의 시간 방향만 확인한다. 과거 행이 나중에 수정된 상황은 이 테스트로 검증할 수 없다. 별도 코드로 재계산한 이력·수량 대사도 산술 확인이며 당시 상태 가용성을 입증하지 않는다. 실제 운영 범위에서 미관측 사례를 평가할 때는 고정 예측 기간이나 검열을 다루는 평가를 별도로 설계해야 한다.

단일 6:2:2 분할과 피처 생성은 실행했다. 여러 시점의 rolling-origin 평가, baseline 오차, XGBoost 학습, 시험 점수는 아직 실행하지 않았다. 다음은 6단계의 비교용 예측과 평가 기준이다. 이후 학습을 수행하더라도 현재 자료의 탐색 실험 한계를 명시해야 한다.

재현:

```bash
python3 -m scripts.build_features_and_splits data/purchase-events-v4 --config config/time-split-v1.json --output-dir data/features-splits-v1
python3 -m unittest discover -s tests
```

기존 출력 폴더는 덮어쓰지 않는다. [실행 집계](evidence/features-splits-v1.json)에 입력·설정·출력 해시, 열 허용목록과 경계별 제외 수를 기록한다.
