# 충전 상품과 테스트 계정 제외 결과

2026-09-16. 사용자가 만월플러스는 보너스 적립금을 지급하는 선불 충전 상품이라고 설명했다. 상품코드 235, 236, 327, 1644, 1645, 1646을 재고 구매 이력·정답에서 제외했다. 같은 코드에 기록된 과거 임시개인결제창 명칭도 함께 적용한다. 실제 상품과 함께 결제한 주문은 해당 충전 상품만 제외하며 고객 전체를 제외하지 않는다. 적립금을 사용한 정상 구매는 현금 결제액 0원을 이유로 제외하지 않는다.

사용자는 테스트 계정명이 정확히 `테스트`라고 알려줬다. 기존 이름 포함 CSV에서는 찾지 못했으나, 현재 주문 기간의 회원을 BigQuery에서 조회한 결과 1개 계정이 확인됐다. 원본 주문과 회원 정보에 쓰기는 수행하지 않았다.

| 조회 결과 | 수 |
|---|---:|
| 주문 기간 내 상품 행이 있는 고객 | 4,044 |
| 최신 이름이 정확히 테스트인 계정 | 1 |
| 테스트 문자열이 포함된 최신 이름 계정 | 1 |
| 이용 가능한 회원 버전 이력에서 테스트 이름 확인 계정 | 1 |
| 회원 정보 연결이 없어 이름 미확인 | 7 |

테스트 계정의 주문은 11건·11행이며 전부 취소 완료였다. 기존 상태 정책에서도 정답에 포함되지 않았으므로 테스트 제외 때문에 정답 수가 추가로 감소하지는 않았다. 이제 회원코드 기반으로 명시적 `exclude_internal_test`를 기록한다. 이름 미확인 7명은 테스트로 추정해 제외하지 않는다. 이 결과가 다른 이름의 테스트 계정 부재를 증명하는 것은 아니다. 조회 job과 로컬 제외 설정 경로는 [실행 집계](preprocessing-applied-v3.json)에 있다.

## 현재 산출물

`data/purchase-policy-v3/`와 `data/purchase-events-v3/`를 새로 생성했다. 기존 버전과 원본은 보존했다. 원본 42,511행을 모두 유지하며 충전 상품 594행과 테스트 계정 11행에 제외 사유를 기록했다. 제외 우선순위는 확인된 테스트 계정 → 충전 상품 → 기존 상태 규칙이다. 제외 행의 `eligible_quantity`는 빈 값이고 날짜 연결의 장벽은 아니다.

제외는 원본 삭제가 아니라 모델에 사용할 구매 이력·정답에서 빠진다는 뜻이다. 확인된 테스트 회원코드의 해당 기간 전체 주문을 제외하며, 이번 자료에서 충전 상품 594행과 테스트 계정 11행은 겹치지 않는다. 나머지 정상 고객의 같은 주문·날짜에 있는 실제 상품은 유지한다. 보고서의 전체 고객·상품 조합 수는 제외 전 대상을 포함한 추적용 수치이며 모델 입력 대상 수가 아니다.

- 정상 구매일: 31,939개
- 다음 재구매 정답: **13,206쌍** (기존 13,587쌍에서 충전 상품 381쌍 제외)
- 보류로 연결을 중단한 출발 구매: 516개
- 다음 구매 미관측: 18,217개

`excluded_only` 날짜는 추적용 기록이다. 모델 입력·구매 횟수·간격·라벨 계산에 넣지 않는다. 원본 연결표는 모든 행을 유지하고 제외 행의 집계 기여는 0이다. 0은 제외 집계값이며 구매 수량 정답이 아니다.

자동 테스트 19개가 통과했다. 충전 상품과 정상 상품의 혼합 주문, 현금 0원인 정상 상품, 테스트 계정 우선 제외와 모든 행 보존을 확인했다. 실제 데이터의 모든 원본 열을 대조했고 제외 대상이 아닌 날짜별 이벤트와 정답 행은 이전 버전과 완전히 일치했다.

```bash
python3 -m scripts.apply_training_policy data/order-items-v2.csv --output-dir data/purchase-policy-v3 --product-exclusions config/product-exclusions-v1.json --customer-exclusions data/test-account-exclusions-v1.json
python3 -m scripts.build_purchase_events data/purchase-policy-v3/rows.csv --policy-report data/purchase-policy-v3/report.json --output-dir data/purchase-events-v3
```

새 출력 경로만 허용한다. 고객 제외 설정은 로컬 `data/`에 저장하고 보고서에 해시를 보존한다. 샘플·사은품 제외는 아직 적용하지 않았다. 모델 학습은 미실행이며 과거 상태 가용성·마감일 완전성 확인은 여전히 남아 있다.
