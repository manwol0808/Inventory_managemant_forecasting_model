# 설계 v0 검토 기록

2026-09-15. 문서·구조 점검의 검증 기록이며 모델 성능 검증 기록은 아니다.

## 실제 실행한 확인

- `python3 scripts/audit_csv.py datase.csv --output docs/evidence/data-profile.json` 실행 성공.
- 원본을 다시 읽어 JSON 직렬화 기준으로 보고서 전체 재현 확인. 첫 비교에서는 Python의 정수 딕셔너리 키와 JSON의 문자열 키 차이로 점검 assertion이 실패했고, 동일한 직렬화 형식으로 비교하도록 점검 코드를 수정한 뒤 통과했다. 원본/집계 알고리즘 수정은 없었다.
- 별도 SQLite 집계로 행 수, 주문 수, 고객×주문×상품 반복 키 수, 완전 반복 추가 행 수, 원본 수량 합계 일치 확인. 이는 계산의 교차 확인이며 CSV가 실제 거래를 정확히 나타낸다는 증거는 아니다.
- 임시 합성 fixture에서 한 주문의 서로 다른 상품과 반복 레코드가 보존되는 것, 열 수 오류와 잘못된 UTF-8을 거부하는 것 확인. 합성 fixture는 모델 정확도 평가에 쓰지 않았다.
- 점검 전후 원본 SHA-256이 [프로필](data-profile.json)의 해시와 일치함을 확인.
- Markdown 문서 10개의 로컬 링크가 모두 존재하고 코드 블록의 시작/끝이 짝을 이루는 것 확인. Grafana/Mermaid 렌더링을 검증한 것은 아니다.

## shower: 맥락 없는 인계 검토

별도 검토 에이전트에게 아키텍처 문서 내용을 전달했다. 대화·저장소·이웃 문서를 보지 않고 읽도록 했다. 범위는 아키텍처 문서 한 개였으며 전체 코드나 모델 평가를 독립 감사한 것은 아니다.

| 지적 | 반영 |
|---|---|
| 예제 origin과 모델 학습 기준일이 혼동됨 | fit_cutoff와 라벨 available_at, 구체적인 날짜 예시 추가 |
| 예측값·SKU 없는 목표·무주문 표현이 없음 | nullable 예측값, target_type, 상태, fallback의 출력 계약 추가 |
| 잠금 테스트 실패 경로와 첫 학습 전 Grafana 단계 불명확 | 실패 시 baseline 유지 흐름, 수집 연결 완료 조건 추가 |

## mandela: 평가 독립성 점검

아직 실행된 모델 평가가 없으므로 아래는 설계상 위험과 예방 조치다.

- **Tautology / 사후 집단 정의:** 모델 결과를 보고 집단·통과 기준을 만들면 판정이 순환한다. 과거 정보로 집단을 정하고 후보/테스트 전에 기준을 동결하도록 했다.
- **Verifier = designer / 검증 재사용:** 학습자가 조기 종료에 사용한 검증 값을 독립 backtest처럼 보고할 수 있다. 내부 early_stop과 외부 backtest, 잠금 final_test를 분리했다.
- **Shared hallucination / 합성 결과:** 에이전트가 만든 더미 결과로 예측 성능을 증명하지 않도록 실제 이후 주문과 재계산 가능한 예측 결과를 요구했다.

실제 라벨 독립성은 원본 SQL·상태 이력과 예제 생성 구현이 있어야 검증할 수 있다. 문서 합의나 에이전트 동의로 대체하지 않는다.

## factchk: 근거 확인

[연구 목록](../research.md)에 각 자료의 원문/저자 출처, 확인 범위, 적용 한계를 기록했다. ε-constraint와 Group DRO는 현재 설계에 관련된 근거이며 동일한 프로젝트 방법의 검증 논문으로 표현하지 않았다. WAPE를 무조건 주지표로 확정하는 대신 목표 통계량에 따라 결정하도록 보완했다. XGBoost·Grafana 수집 방식은 공식 문서를 확인했으며 로컬 설치/실행 검증은 아직 아니다.

사용자의 categorical features 후속 질문에 따라 XGBoost 공식 categorical 문서의 dtype, 재인코딩, 신규 범주, JSON/UBJSON 저장 조건을 확인하고 데이터 계약·Grafana 패널에 반영했다. 이 항목의 실행 테스트는 모델 구현 단계에 남아 있다.

## ssotize: 읽기 전용 일관성 감사

지표/모델/상태 키워드 검색과 문서별 전체 읽기로 교차 확인했다. 별도의 통합·이동 작업은 실행하지 않았다.

| 내용 | 기준 문서 | 다른 문서의 역할 |
|---|---|---|
| 선택/미결 상태 | decisions.md | 구현·평가 문서는 상세 계약, 대화 파일은 역사적 기록 |
| 데이터 원본 숫자 | data-profile.json | data-contract.md는 이 프로필에서 확인한 현황 해석 |
| 수량·시기·집단 판정 | evaluation.md | Grafana는 저장된 판정을 표시하며 별도 공식을 만들지 않음 |
| 첫 모델 | decisions.md의 사용자 선택 | architecture/evaluation은 XGBoost 구현 계획, 연구의 LightGBM은 배경 사례 |

과거 대화의 예시 숫자와 WAPE 제안은 삭제하지 않고 현재 결정과 다름을 표시했다. 사용자 후속 요구인 아이템 추적, Grafana, XGBoost를 현재 설계에 반영했다.

## re0 및 적용하지 않은 절차

현재 설계 본문에서 예정 기술 스택을 XGBoost로 갱신하고, Grafana를 나중에 검토한다는 초기 표현을 첫 학습 전 요구로 고쳤다. 진행 과정 대신 최종 계약이 읽히도록 시간 검증·상태 표현을 정리했다. 원문 보존 파일은 역사 기록이므로 내용 압축 대상에서 제외했다.

`detool`은 도구 중립성/이식성 주장을 하는 산출물이 아니므로 적용하지 않았다. 사용자 호출 중심의 추가 비판/반복 루프도 실행하지 않았다. 이 설계에 따라 학습한 모델, baseline 점수, Grafana 화면은 아직 없으며 대시보드 렌더 검증도 하지 않았다.
