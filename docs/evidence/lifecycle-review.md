# 주문 상태 연결 조사

2026-09-16. 취소·반품·교환을 단순 삭제하지 않고 같은 주문의 상품 항목과 연결하는 조사다. [로컬 집계](lifecycle-summary.json)는 고정된 `order-items-v2.csv`에서 재현했다.

## 확인한 구조

아임웹은 같은 품목의 일부 수량을 별도 섹션으로 나누어 배송·취소·반품할 수 있다. 섹션 상품은 섹션의 상태를 따르고 각 `orderSectionItemNo`에 `qty`가 있다. 따라서 같은 `orderItemCode`가 여러 섹션에 있다는 사실만으로 복제된 행으로 취급하지 않는다. [공식 주문 구조](https://developers-docs.imweb.me/guide/주문-이해하기), [부분 처리 가이드](https://www.imweb.me/qna?mode=faq&q=72247).

최신 스냅샷의 섹션 목록은 시계열 상태 변경 로그가 아니다. 섹션 순서나 상세 번호의 크기로 상태 변경 순서를 추정하지 않는다. 구매확정 3개와 반품완료 3개가 연결된 경우, 두 수량을 무조건 6개의 새 구매 또는 0개의 순구매로 해석하지 않는다. 현재 상태별 수량을 따로 보존하고 목표 정의에 맞게 선택한다.

## 실제 연결 결과

42,511개 원본 행을 `(order_id, order_item_code)` 기준 42,474개 그룹으로 연결했다. 다른 상품이나 다른 주문은 하나의 이력으로 합치지 않는다. 반복 그룹의 상태는 다음과 같다.

| 상태 조합 | 그룹 수 |
|---|---:|
| 구매확정 + 구매확정 | 18 |
| 취소완료 + 구매확정 | 8 |
| 구매확정 + 반품완료 | 4 |
| 취소완료 + 취소완료 | 2 |
| 취소완료 + 반품완료 | 2 |
| 반품완료 3개 섹션 | 1 |
| 구매확정 + 배송완료 | 1 |

`data/lifecycle-v1/source-links.csv`는 모든 원본 레코드와 그룹 판단을 연결한다. `item-groups.csv`의 상태별 수량 합은 점검용으로, 학습 정답이 아니다. 완료 후보 그룹 39,875개, 취소만 있는 그룹 1,511개, 진행 중 그룹 1,029개, 부분 취소 검토 8개, 반품/교환 관련 검토 51개다. 반품 또는 취소와 연결된 구매확정 행도 그룹 단위 검토 대상으로 잡아 단독으로 승인되지 않게 했다.

원본 42,511행 모두 연결되며, 7개 테스트가 통과했다. 이는 연결 로직 검증이며 수요 정답의 업무 타당성이나 모델 성능 검증은 아니다.

## 추가 원본 조회

BigQuery job `job_lOWlqLR5cPMm0_XwxmhzwJPbtFI4`에서 샘플의 `returnInfo`에 `returnReason`, `returnRequestTime`, `isExchange`, `isRefund`, `isRetrieved` 등의 필드가 있음을 확인했다. 승인/완료 시각을 이 접수 시각으로 대신하지 않는다.

같은 주문일 범위의 최신 원본을 조회한 job `job_E6B1jcLzpNFt0X3moraZjzmdkazq` 결과:

| 색상 및 사이즈 변경 | 2 | 2 |

반품 49행 중 47행에 해당 필드의 사유·접수 시각이 있었다. 교환 4행은 조회한 `returnInfo` 경로에서 사유·접수 시각이 없었다. 다른 경로에도 정보가 없다는 뜻은 아니다. 사유와 시각은 아직 로컬 CSV에 조인하지 않았다. 과거 예측 피처에는 그 예측 시점에 알려진 정보만 사용할 수 있다.

## 남은 기준

취소 완료 제외는 승인된 규칙이다. 반품·교환의 확정 정답 기여량, 진행 중 주문의 관측 마감은 아직 미결이다. 이번 작업은 전체 추적과 검토 표시이며 모델 학습이나 실제 수량의 차감·합산 확정은 하지 않았다.

재현: `python3 -m scripts.audit_item_lifecycle data/order-items-v2.csv --output-dir data/lifecycle-v1` (새 출력 폴더 필요).
