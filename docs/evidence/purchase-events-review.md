# 4단계: 구매일 이력과 다음 재구매 정답

2026-09-16. [v1 계약](../purchase-policy-v1.md)을 구현했다. 2026-04-09~2026-09-15 주문의 최신 상태 스냅샷으로 만든 정제 결과다. 실제 학습이나 과거 시점 평가를 실행한 결과는 아니다.

| 항목 | 수 |
|---|---:|
| 원본 상세 행 / 연결표 행 | 42,511 / 42,511 |
| 고객·상품 조합 | 19,759 |
| 정상 구매일 이벤트 | 32,492 |

| 다음 구매가 아직 관측되지 않은 출발 구매 | 18,388 |

정답 쌍은 5,018개 고객·상품 조합에서 나왔다. 정상 구매일이 1회뿐인 조합은 13,881개다. 13,587개 정답 쌍을 원본 주문 행 수나 전체 고객 수와 혼동하지 않는다. 32,492개 정상 구매일 각각에 `observed / blocked_by_hold / right_censored` 중 하나가 붙는다.

3단계 정상 포함 39,821행 중 2행은 같은 고객·상품·날짜의 다른 주문에 보류가 있어 추가 보류됐다. 따라서 39,819행이 32,492개 정상 구매일로 합쳐졌고 수량 합은 56,599개다. 상품마다 포장 단위가 다르므로 이 합계는 연결 대사용이며 소비량·중량 통계가 아니다. 취소·보류 원본 행은 모두 연결표에 남는다.

## 파일과 의미

`data/purchase-events-v1/`에 저장한다.

| 파일 | 내용 |
|---|---|
| `daily-events.csv` | 고객·상품·한국 주문 날짜별 합산, 정상/보류/취소만 상태, 연속 구매 구간 |
| `source-links.csv` | 원본 레코드·상세 ID에서 날짜 기록으로의 연결 및 수량 기여분 |
| `next-purchase-labels.csv` | 모든 정상 출발 구매의 정답 관측/보류/미관측 판정 |
| `observed-pairs.csv` | 날짜·수량·간격 정답을 실제로 연결할 수 있는 쌍 |
| `report.json` | 입력/출력 해시, 집계 및 대사 결과 |

날짜 기록의 ID는 고객·상품·날짜를 함께 해시한 값이다. ID를 익명화 보장이나 모델 피처로 사용하지 않는다. `episode_id`는 보류 없이 이어지는 구매 구간의 첫 정상 이벤트 ID이며, 보류 뒤 첫 정상 구매부터 새 구간이다. `episode_purchase_index`는 그 구간 안에서의 구매일 순번이다.

날짜 범위는 양 끝을 포함한다. 첫 관측 구매나 첫 구간은 고객의 생애 첫 구매를 뜻하지 않는다. 4월 9일 이전 이력이 잘려 있을 수 있으므로 구간 순번을 가입 이후 구매 횟수로 사용하지 않는다. `source_rows`와 `order_count`는 같은 날짜 그룹의 취소·보류 행과 주문도 포함한 감사 집계다.

정답 판정은 취소만 있는 날짜를 제외한 관측 순서를 따른다.

| 바로 다음 날짜 기록 | 출발 구매의 판정 | 정답 필드 |
|---|---|---|
| 정상 구매 | `observed` | 다음 날짜·수량·한국 달력 날짜 차이 |
| 보류 | `blocked_by_hold` | 정답은 빈 값, 첫 보류 기록 ID만 연결 |
| 기록 없음 | `right_censored` | 정답과 보류 기록 ID 모두 빈 값 |

앞부분이나 연속된 보류 날짜에는 출발 구매 정답을 만들지 않는다. 보류 뒤 첫 정상 구매에서 새 구간을 시작한다. `right_censored`는 이 파일 안에 후속 구매가 없다는 표시이며, 충분한 관찰 기간을 확보했다거나 이탈을 확인했다는 뜻은 아니다.

취소만 있는 날짜는 감사 기록으로 남지만 재구매 연결에서는 건너뛴다. 보류 날짜는 건너뛰지 않는다. 연결표의 기여분 0은 집계에서 제외했다는 뜻이며 0개 구매 정답이 아니다. 보류 날짜의 수량과 미관측 정답은 빈 값이다.

`origin_on`은 과거 구매일을 가리키는 연결 기준이며 실제 운영에서 예측을 실행한 시각이 아니다. 시점별 피처와 운영 예측 기준 시각은 5단계에서 정한다. 정답 CSV를 그대로 모델 입력 피처로 사용하지 않는다.

## 검증과 제한

자동 테스트는 같은 날 합산, 상품별 분리, 같은 날 보류 전파, 보류 구간 연결 차단과 새 구간 시작, 취소 날짜 건너뛰기, 미관측 빈 정답, 정상 구매가 없는 입력, 입력 해시 변조, 한국 날짜 불일치 및 기존 출력 보호를 확인한다. 전체 테스트 17개가 통과했다.

원본 42,511행의 연결 및 포함·제외·보류 수량을 대사했다. 별도 점검 코드가 원본 상태부터 날짜별 판정·수량을 재구성해 모든 출력과 비교했고, 모든 정답 연결·간격·연속 구매 구간도 일치했다. 새 임시 경로로 재실행한 네 CSV의 해시는 기존 산출물과 같았다. 포함 수량의 합은 각 정상 날짜의 합과 일치하고, 관측된 정답 쌍의 간격은 모두 양수다. 자세한 수치는 [실행 보고서](purchase-events-v1.json)에 기록한다.

최신 상태가 과거에 알려졌다는 증거는 아직 없다. 관측 시각은 구성 행의 추출 시각 최댓값으로 보존하고 `historical_availability_verified=false`, `training_ready=false`를 유지한다. 마지막 날짜의 하루 전체 수집 여부도 미확인이다. 따라서 현재 결과는 사후 정제 이력·정답이며 모델 성능이나 운영 적용 가능성을 입증하지 않는다. 회귀 예제에서 빠진 보류·미관측 사례를 삭제하거나 전체 성능 계산에서 숨기지 않는다.

재현:

```bash
python3 -m scripts.build_purchase_events data/purchase-policy-v1/rows.csv --policy-report data/purchase-policy-v1/report.json --output-dir data/purchase-events-v1
python3 -m unittest discover -s tests
```

출력 폴더가 이미 있으면 덮어쓰지 않고 실패한다. 재실행에는 새 경로를 사용한다. 다음은 5단계의 과거 피처·시간 분할·시점 가용성 점검이다.
