# 결정 사항과 다음 질문

작성일: 2026-09-15. 결정 상태의 기준 문서다. **확정 방향**은 대화에서 요구한 방향, **제안**은 이번 설계 판단, **미결**은 업무 정의나 데이터 확인이 필요한 항목이다. 실험으로 얻은 결론은 아직 없다.

## 확정 방향

| ID | 방향 | 이유 |
|---|---|---|
| A01 | 수량 예측을 우선하고 시기·집단별 성능은 가드레일로 관리 | 사용자가 제안한 main/sub 구조 |
| A02 | 3D 원점 거리와 z-score로 Champion을 선정하지 않음 | 우선순위를 직접 표현할 수 있음 |
| A03 | 같은 상품 구매가 여러 행에 있다고 바로 삭제하지 않음 | 상품·옵션·분할 처리 정보를 보존해야 함 |
| A04 | 원본, 현재 설계, 대화 이력을 분리해서 보관 | 데이터와 결정 경위를 다시 확인할 수 있어야 함 |
| A05 | baseline을 먼저 측정하고 KR 숫자를 확정 | 제시된 20%·10%p는 측정 결과가 아님 |
| A06 | 각 주문 아이템을 끝까지 추적하고 집계 후에도 원본 연결 보존 | 사용자의 후속 확인: 행이 같아 보여도 아이템별 추적이 필요 |
| A07 | 학습 진행과 평가 결과를 Grafana로 상세 추적 | 사용자의 후속 요청. 패널·수집 경로는 [추적 설계](observability.md)에 정의 |
| A08 | 첫 학습 모델은 XGBoost | 사용자가 명시한 모델. 목적함수와 설정은 목표/단위 확인 후 결정 |

## 이번에 채택한 설계 초안

| ID | 제안 | 판단 및 변경 조건 |
|---|---|---|
| P01 | 단일 로컬 배치 파이프라인 | 파일 규모와 현재 단계에서 작업·결과 재현부터 확보. 서비스는 운영 요구가 생기면 추가 |
| P02 | 원본 → 정제 → 주문/상품 이력 → 시점별 피처·라벨 → baseline → 후보 학습 → 평가 → 선정 | 각 단계의 계약과 실패 원인을 분리 |
| P03 | 집단별 모델 분리보다 전체 고객·상품을 함께 학습하는 모델부터 비교 | 짧은 이력에 대한 초기 가설. 집단 분리는 시간 검증에서 개선될 때만 채택 |
| P04 | 시기 조건 AND 각 주요 집단의 동일 집단 baseline 비교 | 좋은 한 지표가 다른 실패를 상쇄하지 않음 |
| P05 | 학습과 독립 평가 역할 분리 | 평가자는 모델 구조를 좋아하는지보다 고정된 기준으로 성능을 확인 |
| P06 | 규칙 기반 고객군·상품군으로 시작 | 군집 알고리즘 도입 전에 설명 가능한 성능 단면 확보 |
| P07 | XGBoost native categorical 경로를 우선 검토하고 ID의 숫자 크기 해석 방지 | [범주 사전·신규 범주·저장 규칙](data-contract.md). 사용자 지적에 따라 별도 검증 계약 추가 |

## 다음에 하나씩 확정할 항목

| 순서 / ID | 질문 | 현재 권고 | 확정에 필요한 정보 | 답 전에도 할 수 있는 일 |
|---|---|---|---|---|
| 1 / D01 | 다음 주문 한 건인가, 향후 H일 총주문량인가? | 재고 준비라면 고객×상품×향후 H일의 예상 수량 | 실제 사용 업무, 예측 갱신 주기, H일, 납기 | 구조 점검, 중복 원인 확인 |
| 2 / D02 | 수량 1의 단위와 SKU는 무엇인가? | 옵션까지 구별되는 판매 단위. 중량 변환은 확인된 규격만 | 상품/옵션 마스터, 묶음 구성, 중량 | 필요한 컬럼과 조인 계약 설계 |
| 3 / D03 | 취소·반품을 어떻게 정답에 반영할 것인가? | 최초 주문, 출고, 순수요 중 실제 업무와 맞는 하나 선택 | 상태 정의, 부분 취소·반품 수량, 발생 시각 | 상태별 건수 및 SQL 조인 점검 |
| 4 / D04 | CSV 반복 행의 원인은 무엇인가? | 주문 상세 식별자로 추출 중복과 실제 구매를 구별 | 원본 SQL, order_line_id, option_id, 섹션/출고 ID | 반복 개수·금액 일치 여부 확인 |
| 5 / D05 | 평균 수량·대표 수량·재고 서비스 수준 중 무엇을 맞출 것인가? | 재고용 기대 수량이면 평균 예측과 제곱오차 계열을 우선 검토 | 과소·과다예측 비용, D01·D02 | 지표별 장단점 문서화 |
| 6 / D06 | 시기 오차는 며칠까지 허용 가능한가? | 날짜 MAE와 허용 일수 내 비율부터 측정 | 리드타임, 알림/발주 준비에 필요한 시간 | baseline 정의 |
| 7 / D07 | 어떤 집단까지 통과를 보장할 것인가? | 이력량·재구매 간격·상품 인기도 기준, 표본 수와 coverage 동반 | 정제 후 분포, 주요 업무 집단 | 집단 정의안 작성 |
| 8 / D08 | KR 한도와 최소 개선폭은 얼마인가? | 개발용 baseline 결과와 업무 허용치로 고정 | D01–D07, 시간 검증 결과 | Champion 판정 알고리즘 설계 |

질문은 1–2부터 받는다. 답이 없는 항목은 미결로 유지한다. 특히 예측 기간·단위·라벨을 추정해 학습 성능을 발표하지 않는다. 승인과 실험 전 의사결정은 구분하며, 단순 구현·점검 작업마다 재승인을 요구하지 않는다.

## 대화 이후 보완한 판단

- 이전 응답의 수량 WAPE는 **후보 지표**다. 재고 기대 수량을 예측하는 경우 WAPE 단독 최적화가 적합한지는 별도로 확인한다. [이유와 대안](evaluation.md), [연구 R02·R03](research.md).
- min–max와 최악 집단 오차만으로는 집단별 악화를 충분히 제어하지 못한다. 집단마다 그 집단 baseline과 비교한다.
- 고객·상품의 행을 합치는 작업과 고객·상품별 학습 모델을 분리하는 작업은 서로 다르다.
- 장기 미구매와 다음 주문 미관측은 구분한다. 관측 종료 때문에 아직 정답을 모르는 경우가 있다.
