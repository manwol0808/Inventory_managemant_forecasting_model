# 고객 유형별 멀티 에이전트 재구매 예측 아키텍처

이 문서는 기존 `xgboost-short-v2` 챔피언을 보존하면서 고객의 구매 패턴에 따라 예측 에이전트를 선택하는 challenger 구조를 정의한다. 목표는 재구매일을 정확히 맞히는 것보다 실제 소진 전에 일요일 밤 또는 월요일 발주 시점에 장바구니 제안을 만드는 것이다. 늦은 제안은 큰 비용으로 취급하고, 약간 이른 제안은 허용한다.

## 라우팅 트리

모든 판단은 예측 origin 시점 이전의 구매 이력만 사용한다. 고객을 한 모델에 영구 배정하지 않고, 새로운 구매가 관측될 때마다 고객-품목 조합의 유형을 다시 계산한다.

```text
이 품목 첫 구매? → 장바구니 담지 않음 (skip_first_purchase)
고객-품목 이력 충분? (최근 간격 4개 이상)
├─ 아니오 (2~4번째 구매) → 전체 챔피언
└─ 예 → 최근 구매 주기 패턴
   ├─ 짧아졌다가 다시 길어짐 → 전체 챔피언
   ├─ 주기가 점점 짧아짐     → speeding_up TabPFN (50분위)
   ├─ 주기가 점점 길어짐     → slowing_down TabPFN (50분위)
   ├─ 주기가 안정적임        → 전체 챔피언
   └─ 방향성 없는 불규칙     → 전체 챔피언
```

현재 설정(2026-09-17 최종)은 위 트리다. 아래 "에이전트 역할"과 25분위 결과는 이 구성에 이르기까지의 기록이다. 평가 기준은 45일 모니터링 안에 다시 산 경우의 날짜 ±7일 적중이며, 45일(또는 예측일+7일 중 늦은 날) 안에 사지 않으면 제안을 닫는다(`monitor_until`).

기본 분류 기준은 최근 간격 4개 이상, 최근 간격 최대 6개, 안정 주기 CV 0.25 이하, 추세 상대 변화량 30% 이상, 같은 방향 간격 비율 75% 이상으로 시작한다. 반등·추세를 안정성보다 먼저 판정한다. 이 값들은 독립적인 시간 검증에서 조정한다.

## 에이전트 역할

### Stable XGBoost

구매 간격이 안정적인 고객-품목 조합을 담당한다. 기존 XGBoost feature에 cadence와 item-speed feature를 추가하고, `gap_days`는 25·50·75 분위수를 한 모델로 학습해 **25분위**를 예측일로 쓴다(`point_quantile`). `cart_quantity`는 절대오차 모델로 따로 학습한다.

### Speeding-up TabPFN

주기가 짧아지는 조합을 담당한다. 같은 cadence·item feature로 25·50·75 분위수를 예측하고 25분위를 쓴다. 수량은 최근 3회 중앙값이다. 표본이 부족하거나 불확실성이 높으면 챔피언으로 fallback한다. 설정에서 `speeding_up_xgboost`로 바꿀 수 있다.

### 챔피언에 맡기는 유형

검증 1,196건에서 시도한 뒤 챔피언으로 돌렸다. 늦은 제안은 주간 발주 일정 기준이다. 모두 이미 사용한 검증이며 30일 이내 재구매만 포함하므로 긴 주기에 대한 판단은 아니다.

| 유형 | 시도 | 결과 | 챔피언 |
|---|---|---|---|
| 불규칙 (596건) | 품목 구매자 주기 통계 | 늦음 58.1%, ±7일 26.7% | 늦음 4.0%, ±7일 73.5% |
| 이력 부족 (319건) | 품목 통계 | 늦음 36.3% | 늦음 5.7% |
| 반등 (8건) | TabPFN 50분위 / 25분위 | 늦음 3건 / ±7일 챔피언과 같음 | 늦음 0건 |
| 점점 길어짐 | 없음 | 늦은 예측을 따라가는 모델은 운영 목적과 맞지 않음 | |

품목 통계는 자주 사는 고객이 간격을 더 많이 기여하고, 예측 간격 중앙값이 26일로 실제 10일보다 길었다. 현재 데이터에는 카테고리 컬럼이 없다.

## 유형 전환 안정화

간격 하나 때문에 라우트가 흔들리지 않도록 hysteresis를 적용한다.

- 새 유형이 2회 연속 관측될 때만 전환한다.
- 또는 최근 3개 관측 중 2개가 같은 유형일 때 전환한다.
- 애매한 경우 이전 유형을 유지한다.
- 이력이 다시 부족해지면 즉시 챔피언을 사용한다.
- 유형, 선택 에이전트, fallback 여부, 입력 feature snapshot을 로그로 남긴다.

## 늦은 제안 방지

전문모델과 전체 챔피언의 결과를 비교할 수 있게 한다.

```text
전문모델 불확실성이 높음       → 챔피언 fallback
전문모델 표본이 부족함          → 전문모델 사용 금지
전문모델 예측일이 챔피언보다 늦음 → late_guard가 켜진 경우만 챔피언 선택 (현재 꺼짐)
```

late_guard를 켜면 전문모델은 118건 중 107건이 챔피언보다 늦어 사실상 챔피언만 남았다. 그래서 규칙을 끄고, 전문모델 자체를 25분위로 이르게 예측하도록 했다.

| 일정형 118건 | 늦음 | ±7일 | 날짜 MAE |
|---|---:|---:|---:|
| 챔피언 | 5 | 81.4% | 4.68 |
| XGBoost 50분위 | 12 | 89.8% | 4.34 |
| XGBoost 25분위 | 7 | 92.4% | 3.64 |

짧아짐 11건은 TabPFN 25분위가 늦음 0건, ±7일 81.8%(챔피언 63.6%)였다. 2건 차이라 결론이 아니다. 25분위는 이 검증 결과를 본 뒤 고른 값이다.

전체 1,196건 결과는 늦음 67건에서 69건(5.60%→5.77%), 날짜 ±7일 72.99%에서 74.25%, 날짜 MAE 5.56에서 5.44다. 수량 ±2는 97.32%로 같다(`artifacts/multi-agent-router-v1-q25/`).

90일 관찰 구간(2026년 4~6월 출발 15,491건, 재구매 7,551건)에서는 구간마다 챔피언 방식(같은 피처·목적함수·반복 수)을 전체 이력으로 다시 학습해 비교했다(`artifacts/multi-agent-router-v1-mature90/`).

| 90일 관찰 | 건수 | 늦음 챔피언→라우터 | ±7일 | 30일 넘게 이른 제안 |
|---|---:|---|---|---|
| 전체 | 7,551 | 16.08% → 15.60% | 41.60% → 41.33% | 18.45% → 18.91% |
| 일정 (XGBoost) | 478 | 6.1% → 2.3% | 62.8% → 56.5% | 10.7% → 16.1% |
| 짧아짐 (TabPFN) | 125 | 15.2% → 0.8% | 53.6% → 61.6% | 12.8% → 20.0% |

세 구간 모두 늦은 제안이 줄었다. 짧아짐 TabPFN은 늦음과 ±7일이 함께 좋아졌고, 일정 XGBoost 25분위는 긴 기간에서 너무 이르게 기울었다. 90일 안에 다시 사지 않은 7,934건은 두 모델 모두 100% 90일 안에 장바구니가 잡힌다.

월별 12개 구간(재구매 28,604건, 미재구매 29,892건, `artifacts/multi-agent-router-v1-walkforward/`)에서도 방향은 같았다. 늦음은 19.68%에서 19.26%로 줄었고 12개월 모두 줄었다. 일정형(1,983건)은 늦음 8.2%에서 4.3%, ±7일 57.9%에서 54.4%, 30일 넘게 이른 제안 12.2%에서 16.7%였다. 짧아짐(477건)은 늦음 15.1%에서 5.9%, ±7일 44.2%에서 47.0%, 30일 넘게 이른 제안 13.8%에서 22.0%였다. 2026년 1월은 출발 10,800건 중 9,429건이 이력 부족이고 늦음이 43%로 튄다.

날짜 ±7일 적중과 제때 담긴 비율은 다른 질문이다. 라우터 재구매 28,604건에서, 전주 월요일 규칙은 적중했지만 늦게 담긴 사례가 736건(2.6%), 같은 주 월요일에 담으면 3,946건(13.8%)이다. 제때 담긴 합계는 각각 74.9%, 59.0%다. 여기서 제때는 담는 월요일이 실제 구매일보다 앞선 경우다.

불확실성은 `(75분위 − 25분위) / 50분위`이며 1.0을 넘으면 높다고 본다(일정형 4건).

장바구니는 예측 재구매일이 속한 주의 **전주 월요일**에 들어가도록 한다. 3주 후 목요일에 재구매가 예상되면 2주 후 월요일 발주에 쓰도록 전날인 일요일 22:00(한국시간)에 준비한다. 예측 요일에 따라 여유는 7~13일이다. 그 시점이 이미 지났으면 예측일 전에 다음 일요일 밤이 오는 경우 그때, 아니면 즉시 제안한다(`weekly_cart_schedule`).

주 1회 고객(최종 예측 간격 7일 이하, `weekly_buyer_max_gap_days`)은 예외다. 주중 즉시 제안 대신 다음 일요일 22:00에 담고, 가용 시점이 월요일이면 그날 바로 담는다. 검증 1,196건 중 549건이 해당하며, 일요일/월요일 제안이 93.3%에서 100%로 늘고 늦은 제안은 4.43%에서 5.60%로 늘었다.

## 데이터 누수 방지

- 고객 유형과 품목 통계는 각 origin 날짜 기준으로 다시 계산한다.
- 미래 재구매일, validation 이후 품목 통계, 전체 기간으로 미리 계산한 고객 유형을 feature에 넣지 않는다.
- 같은 validation을 반복 조정에 사용한 경우 exploratory 결과로 표시한다.
- 최종 채택 전에는 시간상 더 미래인 독립 holdout을 사용한다.

## 평가 지표

기존 챔피언과 동일한 validation origin에서 1차 비교하고, 독립 holdout에서 재검증한다.

예측 지표: date MAE, 재구매일 ±7일 적중률, quantity ±2 적중률.

운영 지표: 늦은 제안 비율, 실제 구매일보다 1~10일 이른 제안 비율, 최소 7일 이른 제안 비율, 30일 이상 지나치게 이른 제안 비율, 일요일 밤/월요일 발주 스케줄 적용 비율, 고객별 late rate의 macro 평균.

라우팅 지표: 유형별 표본 수와 route 선택 횟수, 유형별 성능, fallback 비율, 고객 유형 전환 횟수, 전환 전후 late rate, 전문모델이 챔피언보다 늦게 예측한 비율.

## 구현 산출물

기존 챔피언 파일은 수정하지 않는다. 라우팅·유형 전환 안정화·품목 통계·평가는 한 스크립트에 둔다.

```text
config/multi-agent-router-v1.json     라우트·문턱·분위수·주간 일정
scripts/run_multi_agent_router.py     학습·라우팅·평가
scripts/tabpfn_worker.py              분위수 출력 지원 (별도 프로세스)
tests/test_multi_agent_router.py
```

실행: `.venv/bin/python -m scripts.run_multi_agent_router` → `artifacts/multi-agent-router-v1-walkforward/` (`predictions.csv`, `champion-schedule.csv`, `report.json`). 입력은 `run_purchase_segments`가 만든 전체 이력 `enriched-origins.csv`다. 챔피언 검증 구간(학습 정답 마감 2026-07-13, 실제 챔피언 예측으로 fallback)과 config `mature`의 월별 90일 관찰 12개 구간(2025-07~2026-06 출발, 매달 전날까지의 데이터로 학습)을 함께 평가한다.

각 예측 결과에는 다음 필드를 포함한다.

```json
{
  "customer_id": "...",
  "product_id": "...",
  "customer_group": "stable",
  "selected_agent": "stable_xgboost",
  "fallback_agent": null,
  "predicted_gap_days": 28,
  "predicted_repurchase_on": "2026-09-16",
  "cart_on": "2026-09-07",
  "cart_at": "2026-09-06T22:00:00+09:00",
  "route_confidence": 0.82,
  "route_changed": false,
  "reason": "stable_customer_pair"
}
```

## 채택 기준

새 구조는 다음 조건을 모두 만족할 때만 challenger 우위로 판단한다.

- 기존 챔피언보다 late rate가 낮거나 같음
- early 1~10일 비율이 개선됨
- 30일 이상 이른 제안이 급증하지 않음
- 독립 holdout에서도 같은 방향의 개선이 확인됨
- fallback이 비정상적으로 많지 않음
- 한 고객군의 개선 때문에 전체 성능이 악화되지 않음

조건을 충족하지 못하면 기존 챔피언을 유지하고, 어떤 에이전트와 고객군에서 문제가 발생했는지 분리해 분석한다.

## ±7일 기준 모델 선택 (2026-09-17)

장바구니를 전주 월요일로 고정하고 날짜 ±7일만 보기로 해서, 모든 유형을 50분위 XGBoost와 50분위 TabPFN으로 각각 예측해 챔피언 방식과 비교했다(`artifacts/multi-agent-router-v1-all-{xgboost,tabpfn}-q50/`, [집계](evidence/multi-agent-router-selection-v1.json)). 25년 7월~26년 3월로 고르고 26년 4~6월로 확인했다.

| 유형 | 고름 구간 건수 | 챔피언 / XGB / TabPFN (고름) | 확인 구간 건수 | 챔피언 / XGB / TabPFN (확인) |
|---|---:|---|---:|---|
| 이력 부족 | 9,638 | 27.1 / 27.0 / 26.4 | 3,636 | 29.4 / 29.9 / 30.2 |
| 불규칙 | 9,055 | 51.9 / 52.4 / **53.8** | 3,102 | 52.3 / 52.8 / 51.7 |
| 일정 | 1,505 | 56.4 / 54.9 / **58.1** | 478 | 62.8 / 59.6 / 61.7 |
| 점점 짧아짐 | 352 | 40.9 / 45.7 / **46.0** | 125 | 53.6 / 49.6 / **55.2** |
| 점점 길어짐 | 406 | 40.2 / 38.2 / **41.6** | 161 | 36.6 / 36.6 / **39.1** |
| 짧아졌다 길어짐 | 97 | 54.6 (전문모델 표본 부족) | 49 | 46.9 / 40.8 / 42.9 |

고름 구간의 TabPFN 우위는 일정·불규칙에서 확인 구간까지 이어지지 않았다. 유형별 모델 차이는 1~5%p이고, 가장 큰 손실은 전체의 46%이면서 적중 27%대인 이력 부족이다.

이력 부족 13,274건(월별 90일 재구매) 중 7,843건(59%)은 고객 전체 방문 간격도 4개 미만이고 적중 24.7%다. 나머지 5,431건(41%)은 고객 주기 유형은 판정되지만 이 품목 간격이 부족한 경우이며 적중은 30~39%다. 고객의 첫 구매일 출발은 3,147건이고 적중 19.0%다.

## 45일 모니터링 기준 (2026-09-17)

사용자가 관찰 기간을 45일로 정했다. 챔피언 방식으로 관찰 기간별로 보면 30일은 90일 재구매의 66.9%, 40일은 77.6%를 잡고, 45일 이후에는 전체 구매 건 대비 적중이 거의 늘지 않는다(19.2%→19.9%). 일정형 주기 중앙값은 27.5일, 75%가 40.5일 이하다.
