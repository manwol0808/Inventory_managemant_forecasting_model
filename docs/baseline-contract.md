# 첫 기준 모델과 평가 계약

고객·상품별 다음 정상 구매일과 그날 주문 개수를 예측한다. 구매일의 전체 주문이 알려진 다음 한국 자정에 예측하며, 아직 구매하지 않은 고객·상품 조합은 이 실험의 대상이 아니다. 옵션 선택은 앱이 처리하고 수량은 상품 개수 그대로 사용한다.

정상 구매·상태 보류·동일 날짜 집계는 [구매 상태 계약](purchase-policy-v1.md)을 따른다. 보류 날짜를 가로질러 간격을 연결하지 않으며 이후 정상 구매부터 새 이력을 시작한다. 최신 입력은 [v4 전처리](evidence/preprocessing-applied-v4.md)다.

## 점수를 보기 전에 고정한 규칙

[설정](../config/baseline-v1.json)과 [실행 코드](../scripts/run_baseline.py)를 함께 버전 관리한다.

- 수량: 같은 고객·상품의 직전 구매일 총개수.
- 재구매 간격: 보류 장벽 이후 같은 고객·상품의 과거 간격 중앙값. 간격 하나부터 사용한다.
- 개인 간격이 없으면 학습 구간에 관측된 같은 상품의 재구매 간격 중앙값을 사용한다. 상품 간격이 5개 미만이거나 미등록 상품이면 전체 학습 간격 중앙값을 사용한다. 5는 이번 실험의 사전 고정 규칙이며 최적값이라는 주장이 아니다.
- 대체 간격은 `train_pool`의 정답만으로 적합하고 검증 기간에는 고정한다. 검증 중 개인 이력 피처는 예측 시점까지 갱신하지만 미래 정답은 사용하지 않는다.
- 간격은 0.5를 올림해 최소 1일로 만든다. 예측일은 **출발 구매일 + 간격**이다. 1일이면 예측을 실행하는 당일이다.

## 측정 기준

수량 RMSE를 첫 후보 비교의 주지표로 사용한다. 큰 수량 오류에 더 큰 비중을 주는 초기 선택이며, 업무상 과소·과다 비용이 확정되면 새 평가 버전으로 변경한다. 보조 지표는 수량 MAE, WAPE, 평균 편향, 정확 일치율이다. 상품별 서로 다른 물리 용량은 환산하지 않으므로 합계·WAPE는 카탈로그 개수 기준이다.

날짜는 정수 예측일의 MAE, 편향, ±7일 이내 비율을 측정한다. 7일은 분포를 설명하기 위한 기준이며 업무 승인 한도가 아니다. 시기·집단별 통과 조건과 최소 개선폭은 미확정이므로 `guardrail_status=unassessed`를 유지한다.

이력 집단은 보류 이후 관측 구매 횟수 1회 / 2회 / 3~5회 / 6회 이상이다. 1회는 이번 데이터 구간·에피소드에서 첫 구매라는 뜻이며 생애 첫 구매라는 뜻이 아니다. 각 집단의 표본 수와 동일 지표를 기록하고 상품/전체 대체 규칙 사용 집단도 별도로 기록한다. 고객마다 가중치를 같게 하지 않고 정답 쌍마다 같은 비중을 준다.

## 시간 분리와 결과의 범위

적합은 2026-04-09~07-13 출발 구매 중 07-13까지 정답이 알려진 6,579쌍이다. 검증은 07-14~08-14 출발 구매 중 08-14까지 정답이 알려진 1,196쌍이다. 검증 출발 구매 총 5,633개 중 21.2%이며, 경계를 넘어 재구매한 1,375개·다음 구매 미관측 2,928개·상태 보류 장벽 134개는 점수의 분모에서 제외한다. 짧은 재구매 간격에 유리한 선택 편향이 있다.

여기서 마감일까지 정답이 알려졌다는 표현은 **구매 날짜 기준으로 마감일 전체를 포함한다는 탐색용 가정**이다. 학습은 07-14 한국 자정에 마감하며 첫 검증 출발일 07-14의 예측 시각은 07-15 자정이다. 실제 정상 상태의 당시 가용성을 보장하는 표현은 아니다. 학습 간격이 0개이면 임의 간격을 채우지 않고 실행을 실패시킨다.

원본이 최신 상태 스냅샷이어서 당시 정상 상태가 실제로 알려졌는지는 검증되지 않았다. 결과는 **사후 정제 탐색 점수**이며 운영 성능이나 재고 소진 정확도가 아니다. 미구매 확률·현재 재고·매일 다시 예측하는 정책도 측정하지 않는다. 자세한 한계는 [피처·분할 계약](feature-split-contract.md)을 따른다.

`final_test.csv`와 전체 출발 구매 파일은 실행 코드가 열지 않는다. 최종 시험 지표를 계산하거나 후보 선택에 사용하지 않는다. 입력 파일 해시·기간·개수·정답 간격을 확인하고 예측 함수에는 4개의 허용 피처만 전달한다.

## 실행과 산출물

```bash
python3 -m scripts.run_baseline data/features-splits-v1 --output artifacts/baseline-v1
python3 -m unittest discover -s tests
```

기존 출력은 덮어쓰지 않는다. 한 번에 한 실행만 사용한다. `model.json`에 적합한 간격을 저장하고 다시 읽어 검증 예측한다. `validation-predictions.csv`에는 실제값·예측값·날짜·대체 규칙·원본 연결 키를 저장한다. `report.json`은 집계 점수·coverage·제한·입출력 해시, `events.jsonl`은 실행 이벤트다. 개인별 파일은 Git에서 제외되는 로컬 artifacts에만 둔다.

`artifacts/monitoring/latest.json`은 ID 없는 집계 상태다. 상시 exporter가 완료 후에도 제공한다. 새 실행은 이전 지표를 비우고 실패/완료와 마지막 성공 시각을 구분한다. [Grafana 구성](observability.md)은 개별 고객·상품 식별자와 최종 시험 점수를 노출하지 않는다.
