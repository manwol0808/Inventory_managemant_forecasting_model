# 평가와 학습 설계

첫 최종 시험 786건을 사용한 뒤, 주기 우선·생존분석·TabPFN 개발 비교를 실행했다. [최신 실행 결과](evidence/timing-model-comparison-v1.md), [이전 시험 동결](full-history-experiment.md). 운영 승인은 보류이며 기존 시험 구간은 사용 완료했다. 아래 첫 실험 수치와 후속 설계를 최신 실행 상태와 구분한다. 목표·단위·임계값은 [결정 문서](decisions.md)를 따른다.

현재 목표는 고객·상품별 다음 정상 재구매 날짜와 그날 개수다. [v1 계약](purchase-policy-v1.md)의 보류 장벽·미관측·상태 관측 시각 제한을 우선 적용한다. 아래 H일 합계와 구매 발생/수량 분리 모델은 후속 대안이며 v1의 정답이 아니다. 현재 스냅샷만으로 엄격한 과거 시점 평가를 통과했다고 주장하지 않는다.

## 현재 주기 우선 실험

후속 사용자 요청으로 [주기 비교 v2](timing-experiment-v2.md)는 고객 평균 날짜 MAE를 우선하며 수량 ±1·±2개 비율을 함께 보고한다. [생존분석 비교](survival-experiment-v1.md)는 향후 7일 구매 확률의 고객 평균 Brier를 우선하며 추천 정밀도·재현율을 함께 보고한다. 두 실험은 같은 2026년 4·5·6월 출발 구매를 60일씩 관찰하는 개발 비교다. 무작위로 새 6:2:2를 만드는 방식이 아니며, 이미 사용한 최종 시험을 새 독립 시험으로 부르지 않는다. 아래 수량 우선 기준은 첫 실험의 기록이다.

## 1. 첫 실험의 주지표와 가드레일

선정 문제는 `수량 오차 최소화`, 제약은 `시기 조건 충족 AND 집단별 조건 충족`이다. 가드레일을 평균내지 않는다. [ε-constraint 관련 근거](research.md).

### 수량 주지표는 목표 통계량과 함께 확정

| 필요한 결과 | 학습 손실 후보 | 선정 지표 후보 | 판단 |
|---|---|---|---|
| 다음 기간의 기대 수량, 즉 평균 | 제곱오차 또는 비음수 수량에 적합한 손실 | 단위가 같으면 RMSE, 여러 시계열 규모를 맞추려면 RMSSE 계열 | 재고 준비가 목적일 때 우선 검토 |
| 절대 오차를 줄이는 대표 수량, 즉 중앙값 | 절대오차 | MAE / WAPE | 다음 주문의 대표 수량 등이 목적일 때 검토 |
| 부족 위험을 줄이는 분위수 | 분위수 손실 | pinball loss 및 실제 비용 | 비용·서비스 수준이 확보되면 후속 실험 |

첫 탐색 실험은 점수를 계산하기 전에 **수량 RMSE를 주지표로 고정**했다. MAE·WAPE·편향·정확 일치율을 함께 보고한다. 업무 비용이 확정되면 평가 버전을 변경하며 여러 수량 지표 중 결과가 좋은 지표를 사후 선택하지 않는다. 평균·중앙값·분위수와 손실함수의 정합성은 [Gneiting 논문](https://arxiv.org/abs/0912.0902)을 참고한다.

업무용 보고 후보인 `WAPE = Σ|예측 수량 − 실제 수량| / Σ실제 수량`은 합산 단위가 같고 분모가 양수일 때 계산한다. 0 수요 행도 분자의 과다예측에 포함한다. 모든 실제값이 0인 집단은 WAPE 미정의로 표시하고 MAE와 총 과다예측량을 보고한다. WAPE 0.2는 정의한 집계에서 20%라는 뜻이며, 정규화된 임의 점수 0.2가 언제나 20%의 실제 오차를 뜻하지는 않는다.

WAPE만 최적화하면 희소 수요에서 중앙값인 0을 선호할 수 있다. 총량 편향 `Σ예측 − Σ실제`, 과소·과다예측량을 함께 보고한다. 시간에 따른 WAPE 하락은 분모 증가의 영향일 수도 있으므로 같은 기간·같은 대상의 baseline 비교를 사용한다. [WAPE 설명과 한계](https://robjhyndman.com/hyndsight/wape.html).

RMSSE를 채택하면 시계열별 과거 차분 제곱오차를 **학습 구간에서만** 계산해 분모로 사용한다. 집단/상품 가중치, 시간 간격과 계절 lag, H일 합계에 대한 스케일 정의를 평가 버전에 고정한다. 과거 값이 상수이거나 이력이 짧아 분모를 계산할 수 없는 시계열에 작은 상수를 넣어 통과시키지 않는다. 별도 MAE/RMSE 평가와 fallback 범위로 명시하며 전체 coverage를 보고한다. 이 정의가 준비되기 전 RMSSE 점수를 발표하지 않는다.

### 시기 가드레일

- 통과 조건은 `E_T(candidate) ≤ τ_T` AND `E_T(candidate) ≤ E_T(baseline) + δ_T`다. 허용 일수 기준 τ_T와 허용 열화 δ_T는 사전 고정하며 초기 제안은 δ_T=0이다. 값이 미결이면 통과 여부도 미결이다.
- 현재 1차 보고: 다음 구매일까지의 **MAE(일)**를 정답 쌍에 동일 가중치로 계산한다. 고객별 동일 가중치 평균은 후속 대안이다.
- 현재 보조 보고: ±7일 안에 든 비율은 설명용이다. 업무상 허용 일수 k는 D06에서 별도로 정한다.
- 백분율이 필요하면 고객의 과거 양수 구매 간격 중앙값 `s_c`를 기준으로 `|예측 잔여일 − 실제 잔여일| / s_c`를 계산하고 집계 방식을 고정한다. 30일 주기에 3일 오차면 10%다. `s_c`는 origin 이전 정보만 사용한다.
- 이력이 없어 `s_c`를 계산할 수 없으면 일수 MAE로 별도 보고하며 0%로 대체하지 않는다.
- 다음 주문이 아직 관측되지 않은 고객은 미관측으로 표시한다. 충분히 관측한 고정 기간 내 구매 여부도 별도로 보고해, 재구매자만 선택한 날짜 MAE를 전체 고객 성능으로 주장하지 않는다. 검열을 다루는 생존/위험도 모델은 후속 후보이며 최초 회귀 모델의 완전한 해결책으로 주장하지 않는다.

### 집단별 가드레일

고객군과 상품군은 각각 평가하고, 충분한 표본이 있으면 고객군×상품군도 진단한다. 그룹 ID는 정답·후보 예측과 무관하게 과거 정보로 정의하고 모든 후보가 공유한다.

지표 k가 수량 또는 시기일 때, 주요 집단 g에 대해:

`E(candidate, g, k) − E(baseline, g, k) ≤ δ(g, k)`

초기 제안은 `δ=0`, 즉 집단별 비열화다. 잡음 때문에 허용폭을 둘 경우 업무 허용치와 개발 검증으로 정해 테스트 전에 고정한다. baseline 오차가 0이어도 차이 비교는 정의된다. 오차비를 쓰는 보고에서는 이 경우 비율을 미정의로 표시한다.

이는 집단 최악 오차끼리 비교하거나 min–max만 보는 것과 다르다. 한 집단의 baseline 10%가 후보 25%로 악화되면 다른 집단의 개선으로 상쇄할 수 없다. 집단 간 오차 범위는 보조 지표로 남긴다.

최소 표본 수, 최소 고객 수, 기간 길이, 평가 가능한 수요량, 핵심 집단의 최소 coverage는 D07에서 정한다. 표본 부족 집단은 **통과가 아니라 판단 보류**다. 보류 집단을 제거해 전체 적용 가능하다고 발표하지 않는다. 충분히 평가된 범위의 Champion과 범위 밖 fallback을 함께 제시한다.

## 2. 비교 기준 모델

현재 기준 모델은 [직전 수량 + 개인 간격 중앙값 및 대체 규칙](baseline-contract.md)이다. 아래 표는 다른 목표를 채택할 때의 후속 후보이며 이번 실행에서 모두 비교한 것이 아니다. 현재 업무의 실제 예측 로그가 없으므로 **운영 성능 실측값이 아닌 비교용 대리 baseline**이다.

| 목표 | 직전 반복 baseline | 비교할 간단한 대안 |
|---|---|---|
| 다음 고객 구매일 | 마지막 양수 구매 간격을 마지막 구매일에 더함 | 과거 간격 중앙값 |
| 다음 고객 주문의 SKU 수량 | 직전 고객 주문의 SKU별 장바구니 반복, 빠진 SKU는 0 | 과거 주문별 수량 평균/중앙값 |
| 향후 H일 수량 | 직전 H일의 SKU 수량 반복 | 과거 일평균×H, 자료가 충분하면 계절 반복 |
| 상품의 간헐 수요 | 위 방식과 동일한 대상에서 비교 | Croston 계열·TSB 후보 |

고객×SKU의 다음 구매를 목표로 한다면 직전 해당 SKU 구매 수량을 반복한다. **고객의 다음 주문**과 **그 SKU의 다음 구매** baseline을 혼용하지 않는다.

날짜 반복 baseline이 이미 지난 날짜를 출력하는 origin에는 과거 이력만으로 주기를 이어 붙이는 등 재예측 규칙이 필요하다. 이 규칙과 신규·짧은 이력 fallback은 개발 단계에서 고정한다. baseline과 후보는 같은 origin·H·단위·상태·모집단·정답을 사용한다.

공식 baseline은 개발 기간에서 정하고, 검증/최종 테스트에서 결과가 나쁘다는 이유로 더 약한 baseline으로 교체하지 않는다. 현재 업무 로그가 확보되면 별도 열로 비교한다.

## 3. 시간 검증과 과적합 방지

### 현재 구현한 단일 시간 분할 (2026-09-16)

[고객·상품별 과거 입력과 시간 분할](feature-split-contract.md)이 현재 단일 탐색 실험 계약이다. 출발 구매일 기준 학습 2026-04-09~07-13(96일), 검증 07-14~08-14(32일), 시험 08-15~09-15(32일)로 나눴다. 이는 달력 6:2:2이며 고객·상품별 재구매 이력을 먼저 유지한 뒤 공통 경계로 배정한다. 과거 초안인 7월 15일/8월 15일 경계는 사용하지 않는다.

전체 학습 구간 안에서 정답까지 관측된 6,579쌍, 검증 1,196쌍, 시험 747쌍이다. 내부 조기 종료용 분할은 train_core 4,654쌍, early_stop 399쌍이다. 각 구간 종료 뒤에 발생한 다음 구매 정답을 앞 구간에 넣지 않는다. 경계를 넘는 사례·미관측·보류를 별도 보존한다. 긴 주기 사례의 관측 편향과 모집단 대비 평가 가능 비율을 함께 보고한다.

피처는 예측 기준 구매일의 다음 한국 자정 이전 구매 이력만으로 구성했으나, 최종 상태 스냅샷의 과거 관측 가능성은 확인되지 않았다. 현재 엄격한 시점 가용성 통과는 0개다. 따라서 해당 파일은 **사후 정제 탐색용**이며 운영 가드레일 통과 판정에 쓰지 않는다. 마지막 날짜 수집 완전성도 미확인이다.

단일 분할과 피처 생성만 구현했고 시간순 rolling-origin 개발 검증은 후속 작업이다. 실제 날짜로 경계를 만들며 불규칙 주문 행에 기본 행 수 기반 분할을 바로 적용하지 않는다. [공식 TimeSeriesSplit 설명](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html). 시험 점수는 아직 계산하지 않았다.

BigQuery에서 확인한 확보 가능 이력은 2024-10-02~2026-09-16, 24개 달에 걸친 약 23.5개월이다. b2s의 주문별 최신 버전 중 회원 코드가 있는 주문 55,023건, 상품 상세 138,531행이다. 오늘의 미완결 데이터 및 모든 상태를 포함하며 역사적 누락이 없다는 보장은 아니다. [범위 조회 기록](evidence/history-availability.json).

권고: 더 긴 원본을 확보하되, 개발 검증에서 사용 가능한 최근 약 6개월·12개월·최대 이력을 같은 평가 구간으로 비교한다. 최대 이력은 전체 보유 기간을 무조건 각 fold에서 사용할 수 있다는 뜻이 아니라 해당 fold 시점 이전에 확보된 이력이다. 테스트는 선택된 한 구성의 마지막 평가에만 사용한다. 12개월 또는 24개월이 무조건 더 낫다는 결론은 아직 없다.

컴퓨터에서 확인한 메모리는 16 GiB, CPU 수는 10이다. 약 13.9만 상세 행은 단순한 수치 피처 중심의 CPU XGBoost 첫 실험 대상으로 합리적이라는 추정이며 용량 벤치마크 결과는 아니다. 실제 한도는 학습 예제 수·피처·범주 수·트리 설정·동시 학습 수에 달린다. 고객×상품×날짜 전 조합을 만들면 원본보다 훨씬 커질 수 있다. XGBoost는 외부 메모리 학습을 지원하므로 고정된 개월/행 상한으로 설명하지 않는다. [공식 외부 메모리 문서](https://xgboost.readthedocs.io/en/stable/tutorials/external_memory.html).

과거 구간으로 학습하고 이후 구간을 예측하는 rolling-origin 검증을 사용한다. [시간 검증 원칙](https://otexts.com/fpp3/tscv.html).

1. 마지막 완결 구간을 최종 테스트로 분리한다. 정확한 날짜는 H와 상태 확정 지연을 정한 뒤 고정한다. CSV의 최댓값 날짜가 하루 전체를 포함하는지는 미확인이다.
2. 그 이전 구간에 여러 개발 fold를 둔다. 라벨 구간 `(t, t+H]`가 학습 가능 시점을 넘는 예제는 학습에서 제외한다. 반품 등 확정 지연이 L이면 라벨의 `available_at`도 경계 이하여야 한다.
3. 전처리, 결측 대체, 스케일, 인기 구간, 군집, target encoding은 fold 안의 과거 정보로만 적합한다. `shift` 없는 이동평균, 전체 기간 집계, 현재 등급·최종 상태의 과거 피처 사용을 금지한다.
4. 같은 주문의 상품 행을 무작위로 학습/검증에 나누지 않는다. 동일 고객의 과거가 학습, 미래가 검증에 있는 것은 기존 고객 예측 목적에 맞다. 신규 고객 성능은 별도 단면으로 평가한다.
5. 단순 피처와 제한된 복잡도부터 시작한다. 트리 깊이/리프 수, 최소 리프 표본, 정규화, early stopping을 개발 검증에서 조정한다. 고객별 one-hot 더미를 만들었다는 이유만으로 누수라 하지는 않되, 식별자 암기와 신규 ID 대응을 검증한다.
6. 학습·검증 점수 차이, 시점별 성능, 그룹별 성능을 본다. 검증 자체에 과적합하지 않도록 탐색 횟수/후보 수를 사전 제한하고 실험을 기록한다.
7. 중복 제거·피처·지표·그룹 경계·임계값을 최종 테스트 결과에 맞춰 고치지 않는다. 수정하면 새 실험 버전으로 넘어가며 기존 테스트는 개발 데이터가 된다.
8. 합성 데이터는 날짜 경계, 중복, 분모 0 등 코드 계약 점검에만 사용한다. 실제 일반화 성능은 실제 이후 주문으로 확인한다.

early stopping용 내부 검증과 fold 성능을 보고하는 외부 backtest를 구분한다. 각 fold의 과거 구간을 `train_core → early_stop`으로 나누고 양쪽 라벨이 `fit_cutoff`까지 확정된 데이터만 사용한다. 그 이후의 outer backtest는 트리 반복 횟수 결정에 사용하지 않는다. 개발 fold 결과로 후보를 선택한 뒤 잠금 테스트를 한 번 평가한다. 대시보드의 split 이름도 `train_core / early_stop / backtest / final_test`로 구분한다.

학습 순서는 **baseline → 과거 피처를 사용하는 전역 XGBoost → 필요할 때 XGBoost 발생 여부/양수 수량 분리 모델**이다. 후자의 기대 수량은 `P(구매) × E(수량 | 구매)`로 해석하며, 발생 여부 0인 예제도 평가에서 유지한다. 고객별·상품별 독립 모델이나 군집별 모델은 전역 모델 대비 시간 검증 개선이 있어야 추가한다. [전역 모델·간헐 수요 연구](research.md).

### XGBoost 첫 실험

현재 실행은 [xgboost-v1](xgboost-contract.md)이다. 수량 제곱오차/RMSE, 간격 절대오차/MAE로 각각 학습했다. 연속 수량 최소 1 제한을 주지표에 사용하고 장바구니용 반올림 점수를 별도 보고한다. 아래 목적함수·구조의 다른 선택지는 후속 후보다.

사용자가 첫 학습 모델로 XGBoost를 선택했다. 초기에는 CPU에서 작은 트리로 시작하는 안을 둔다. 기대 수량이면 `reg:squarederror`를 기본 후보로, 비음수 건수 단위면 `count:poisson`을 대안으로 검토한다. 연속 중량·순수요 음수 등 목표 정의가 바뀌면 목적함수를 다시 검토한다. 제곱오차 모델의 음수 예측을 0으로 제한할지는 학습 전에 후처리 규칙으로 정하고 동일하게 평가한다. 기대 수량은 소수일 수 있으므로 개별 예측을 임의 반올림하지 않는다. [공식 목적함수 설명](https://xgboost.readthedocs.io/en/stable/parameter.html).

첫 개발 실험의 설정 초안은 `max_depth=3`, `learning_rate=0.05`, 최대 1,000 boosting round, 50 round 개선 없을 때 early stopping이다. 성능으로 입증된 설정이 아닌 시작점이다. 이후 깊이·학습률·`min_child_weight`·L1/L2·행/열 샘플링을 제한된 범위에서 조정한다. `min_child_weight`는 단순 행 수가 아니라 자식 노드의 Hessian 가중치 합에 대한 조건이다. [공식 파라미터](https://xgboost.readthedocs.io/en/stable/parameter.html).

학습/검증 곡선을 같은 이름·단위로 기록한다. early stopping 대상 validation과 지표를 명시하고, `best_iteration`에 해당하는 모델/예측 범위를 저장한다. 마지막 iteration 모델을 무조건 최적 모델로 취급하지 않는다. Python API 방식은 설치 버전에서 확인하고 best iteration 재현을 테스트한다. [공식 학습·조기 종료 설명](https://xgboost.readthedocs.io/en/stable/python/python_intro.html).

## 4. Champion 판정

1. 지표/평가 버전, 대상, 그룹, baseline, 가드레일 한도, 최소 개선폭을 동결한다.
2. 동일한 개발 fold에서 가드레일을 통과한 후보만 남긴다. 결측 지표·필수 집단의 판단 보류를 자동 통과로 처리하지 않는다.
3. 통과 후보 중 수량 주지표가 가장 낮은 모델 묶음을 선택한다. 개선이 실질적으로 같으면 더 단순한 모델 또는 baseline을 유지한다.
4. 선택한 한 묶음과 baseline을 잠금 테스트에서 비교한다. 실패 시 테스트를 보고 차순위 후보를 계속 시험하지 않는다.
5. 전체 적용 범위, 관측 가능 범위, fallback 비율, 집단별 성능을 함께 보고하고 병행 운영으로 확인한다. 통과 후보가 없으면 Champion 없음으로 기록한다.

불확실성은 고객별 paired error와 기간별 결과로 우선 확인한다. bootstrap을 사용한다면 독립 행 가정으로 주문 아이템을 개별 재표집하지 않고 고객/시간 의존을 고려한다. 신뢰구간이 넓으면 개선을 확정하지 않는다. 통계 절차의 세부 규칙도 결과를 보기 전에 고정한다.

## 5. 구현 시 필수 계약 테스트

- 같은 주문의 복숭아·포도가 서로 추적되면서 고객 주문 횟수는 한 번인지.
- 서로 다른 옵션이 유지되고, 확인된 SQL 중복만 집계 기여에서 빠지는지.
- 원본 상세↔집계 수량 대사가 맞고 제외 사유가 빠지지 않는지.
- 미래 행을 추가해도 과거 origin의 피처/예측 대상/그룹이 변하지 않는지.
- H일 라벨과 확정 지연이 학습·검증 경계를 넘지 않는지.
- 실제 수량 0, baseline 오차 0, 이력 1회, 미관측 다음 주문을 명시적으로 처리하는지.
- 가드레일 하나라도 실패하면 수량 1위여도 탈락하는지. 모든 후보 실패 시 baseline을 유지하는지.
- 범주 순서가 바뀌거나 일부 범주가 빠져도 동일 항목의 의미가 유지되는지. 신규 범주·결측이 정한 경로로 처리되는지. categorical 모델 저장/재로딩 후 예측이 일치하는지. 상세 규칙은 [데이터 계약](data-contract.md)을 따른다.

위 목록 중 미구현된 XGBoost·Champion·다중 fold 검사는 후속 계약이다. 현재 실행해 통과한 범위는 [기준 모델 검증 기록](evidence/baseline-v1.md)을 따른다.
