# 자동 장바구니 연결 계약 초안

현재 연결 대상은 사용자가 지정한 챔피언이며 [등록 파일](../config/champion.json)이 경로와 고정 해시를 관리한다. `scripts.predict_replenishment`는 `--model` 생략 시 이 등록을 읽는 로컬 미리보기 어댑터다. [챔피언 지정과 비교 화면](champion-benchmarks.md)을 따르며 앱 API나 장바구니를 변경하지 않는다. 실제 앱 저장소는 확인 대기다.

## 앱이 보내는 입력

한 요청은 고객·상품의 최신 정상 구매일 하나다. `customer_id`, `product_id`, `origin_event_id`, `origin_on`, `feature_asof`, `history_start`, `latest_purchase_confirmed`, `has_later_purchase_or_hold`, `as_of`, `features`를 받는다. 고객/상품/이벤트 ID는 문자열이다. `feature_asof`는 출발 구매일 다음 한국 자정이며, `as_of`보다 미래일 수 없다. 시각에는 시간대가 필요하다.

`features`에는 [피처 계약](feature-split-contract.md)의 21개 입력만 넣는다. 정답·이름·연락처를 넣지 않는다. 피처의 상품번호는 요청 상품번호와 같아야 한다. 현재 후보는 2026-04-09부터 쌓은 이력으로 적합되어 `history_start`도 그 날짜여야 한다. 전체 이력으로 계산한 누적 피처를 그대로 섞지 않는다. 장기 운영에는 이력 창과 재학습 정책을 별도로 확정해야 한다.

최신 정상 구매가 맞고 이후 구매·보류가 없음을 앱/이력 서비스가 확인해야 한다. 기존 정제 규칙을 통과한 구매만 보내며, 누락 상품·충전·샘플·사은품·테스트 주문은 제외한다. 구매가 없거나 처리 상태가 애매하면 이 어댑터를 호출해 정상 추천처럼 만들지 않는다. 고객·상품별 마지막 완료 구매 뒤 보류가 있으면 자동 추천을 보류한다.

## 반환과 앱 동작

반환은 상품별 `reorder_on`, 연속 `predicted_quantity`, 반올림한 `cart_quantity`, 날짜 도래 여부 `due`, `suggestion_key`, `model_version`이다. 수량 단위는 선택 규격의 개수다. 옵션 선택은 앱이 처리한다. 현재 출력은 항상 `mode=preview_only`, `auto_apply=false`다. `due=true`는 재고 소진이 관측됐다는 뜻이 아니다.

앱 구현 시 다음 상태 처리가 필요하다.

- 같은 `suggestion_key`는 한 번만 적용한다. 키는 고객·상품·출발 구매 이벤트로 만들고 모델 버전 변경으로 중복 담지 않는다. 실제 중복 방지는 앱 저장소의 고유 키/트랜잭션으로 구현한다.
- 사용자가 수량을 수정하거나 제안을 삭제했다면 자동 갱신이 이를 덮어쓰지 않도록 수락/수정/거절 상태를 저장한다.
- 기존 장바구니에 해당 상품·옵션이 있으면 무조건 더하지 않고 사용자의 수량과 합치는 정책을 적용한다. 구체적인 병합 정책은 앱 담당자와 정한다.
- 새 주문·취소·반품·보류가 들어오면 기존 제안을 무효화하거나 재계산한다. 상품 단종·재고 없음·미선택 옵션도 앱에서 확인한다.
- 예측 시점 입력·모델 버전·제안값·사용자 수정·실제 주문을 로그로 남긴다. 향후 유행 급증 대응을 위한 매일 재평가는 현재 구매 직후 예측과 별도 구현한다.

## 적용 전에 남은 사항

앱 저장소/API 위치, 날짜 허용 범위와 통과 비율, 이력별 최소 표본/대체 예측 규칙, 수량 과다 추천 한도, 실제 미래 예측 로그 검증을 확정해야 한다. 모델이 보지 못한 상품은 표시할 수 있지만 자동 적용 승인으로 간주하지 않는다. 현재 원본 상태의 과거 가용성이 확인되지 않았으므로 과거 시험 점수만으로 자동 장바구니 운영을 승인하지 않는다.
