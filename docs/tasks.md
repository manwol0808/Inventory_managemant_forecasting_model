## 첫 단계 실행

아래는 단계별 실행 당시의 기록이다. 현재 상태는 위 표와 [다음 작업 시작점](handoff.md)을 따른다.

2026-09-16 실제 실행: 원본 40,910행 모두 연결, 주문 14,987건, 고객 3,959명. 자동 테스트 3개 통과. 상세 반복 조합 1,857개는 보존했다.

저장소 루트에 `datase.csv`를 준비하고 Python 3의 표준 라이브러리만으로 실행한다. 입력은 [기존 14열 CSV 계약](data-contract.md#사용할-컬럼)을 따른다. 헤더의 이름과 순서가 다르면 실행을 거부한다.

```bash
python3 -m scripts.build_tracking datase.csv --output data/tracking-v1.sqlite
python3 -m unittest discover -s tests
```

출력 경로가 이미 있으면 덮어쓰지 않는다. 재실행에는 새 버전 경로를 사용한다. `data/`는 Git에서 제외된다. 원본 CSV도 변경하지 않는다.

SQLite에는 주문당 한 행인 `orders`, 원본 레코드당 한 행인 `records`, 둘을 연결한 `customer_item_history` 뷰가 있다. 이름·연락처는 복사하지 않는다. 고객 코드는 원본 문자열 그대로 유지한다. 추적 키는 `metadata.source_sha256`와 `source_record_number` 조합이다. 실제 주문 상세 ID를 대신하지 않는다.

고객 이력 조회는 `customer_item_history`에서 `customer_id`를 바인딩한 뒤 `ORDER BY ordered_on, order_id, source_record_number`로 정렬한다. 같은 날의 주문번호 순서는 실제 시간 순서를 뜻하지 않는다.

**이 파일은 추적용 중간 데이터이며 학습용 정제 데이터가 아니다.** 모든 상태와 반복 행을 보존하며 수량은 원문 문자열로 저장한다. `repeated_order_product_keys`는 확인할 반복 조합을 보여줄 뿐 중복 판정이 아니다. 키 누락·날짜/수량 오류·주문 필드 충돌은 일부 행을 버리는 대신 실행 전체를 실패시킨다. 상태·반복 행이 해결되기 전에는 수량을 합산하거나 학습에 사용하지 않는다.

검증 범위: 자동 테스트는 반복 행·취소 상태·문자열 ID 보존, 주문 금액 중복 방지, 덮어쓰기 거부, 잘못된 입력의 실패를 확인했다. 실제 CSV와 조회 결과의 고객·날짜·주문·상품·수량·상태·레코드 번호를 40,910행 전부 대조했고 원본 해시 및 SQLite 무결성도 확인했다. 이는 추적 정확성 검증이며 상품 단위나 정답의 업무 타당성 검증은 아니다.

수량은 선택한 옵션의 개수로 사용하며 옵션 선택은 앱에서 처리한다. 옵션 정보는 초기 진행의 선결 조건이 아니다. 다음은 원본 주문 상세 ID 또는 CSV 추출 SQL로 반복 행 원인을 확인한다.

반복 조합 1,857개 중 모든 열이 동일한 조합은 1,594개, 일부 값이 다른 조합은 263개다. 이는 구조 분류이며 중복 판정이 아니다. [집계 근거](evidence/repeated-lines.json), 로컬 확인 예시 `data/repeated-line-examples.json`에 기록했다.

## 2단계: 상세 식별자 포함 재추출

BigQuery 원본에서 `orderItemCode`, `orderSectionItemNo`, 섹션 식별자를 확인했다. 전체 상태의 최신 주문을 같은 주문일 범위로 조회한 반복 조합 1,929개는 모두 조합 내 상세 번호가 달랐다. 상품 항목 코드가 반복되는 조합도 있어, 식별자가 다르다는 사실만으로 수량 합산을 확정하지 않는다. 기존 CSV의 1,857개와는 상태 필터·추출 시점이 달라 직접 대사한 수치가 아니다.

[새 추출 SQL](../sql/extract_order_items_v2.sql)을 BigQuery에서 실행해 42,511행을 반환했다. 최신 주문을 먼저 선택하고 모든 상태를 보존한다. 주문일 범위는 2026-04-09~2026-09-15로 고정하지만 상태는 현재 스냅샷이다. 이름·연락처와 현재 회원 등급은 추출하지 않는다.

새 형식은 기존 14열 CSV와 다르므로 `build_tracking.py`에 바로 넣지 않는다. 새 CSV의 행 수·식별자·수량 파싱·최신 시각 동률을 확인한 뒤 수집 경로를 추가한다. 주문 금액은 상세 행마다 반복되므로 합산하지 않는다. JSON 해시는 내용 점검용이며 업무 식별자가 아니다. 최신 시각 동률 선택은 정렬로 재현하지만 어느 버전이 업무상 맞는지는 별도 확인한다.

빈 섹션/상품 배열 주문은 상품 행 추출에서 빠진다. 고객 주문 시기 모델에는 주문 단위로 별도 점검해야 한다. 2단계의 상세 추적 데이터 확보·점검은 완료했다. 취소·반품 및 반복 상품 항목 코드의 수량 반영 규칙은 3단계에서 정한다.

### 다운로드 진행 상태

전체 결과의 로컬 다운로드는 10MB 제한으로 21,537행만 저장 가능하다는 경고가 발생했다. 이 파일은 불완전하며 학습에 사용하지 않는다. 주문번호 해시를 3분할해 각각 조회하고 다운로드를 실행했다.

| 분할 | 조회 행 수 | BigQuery job ID |
|---|---:|---|
| 0 | 14,099 | job_imF5m-RAF1HTemXf1BFmhxE0b3xH |
| 1 | 14,130 | job_Ort2X_-BR5Snq4hF4bcBvGPNBjYj |
| 2 | 14,282 | job_--5ZJNTt3nlQURInI_kaW70MLVhn |

저장소 루트의 `dataset3.csv`, `dataset5.csv`, `dataset6.csv`를 확인해 `data/order-items-v2.csv`로 병합했다. `dataset2.csv`는 잘린 파일이며 `dataset4.csv`는 `dataset3.csv`와 바이트까지 같아 병합 입력에서 제외했다. 원본 파일은 모두 그대로 보존한다.

실제 42,511행이 입력 세 파일과 전체 21열 값까지 일치한다. 파일 간 주문 겹침은 없고, 원본 위치 키 및 주문+섹션상품상세번호가 각각 42,511개로 고유하다. 수량 원문은 양의 유한 정수이며 변환 수량과 일치한다. 최신 갱신 시각 동률 주문은 0건이다. 같은 주문+상품항목코드 반복은 36개로 보존했다. [집계와 원본 해시](evidence/order-items-v2.json)를 참고한다.

각 분할은 별도 현재 스냅샷이므로 추출/갱신 시각을 보존한다. 학습용 정제나 수량 합산은 하지 않았다. 기존 14열 수집 스크립트는 이 21열 형식에 사용하지 않는다.

```bash
python3 -m scripts.merge_order_exports dataset3.csv dataset5.csv dataset6.csv --output data/order-items-v2.csv --expected-rows 42511
```

출력이 이미 있으면 새 경로를 사용한다. 전체 값 대조 외에 동일 파일 중복 입력, 파일 간 주문 겹침, 불완전한 행 수를 거부하는 검사도 통과했다.

잘린 최초 파일의 21,537행도 병합본에 모두 존재하고 추출 시각을 제외한 모든 값이 일치함을 확인했다. 전체 조회 42,511행과 분할 합계·실제 파일 행 수를 대사한 범위에서 수집 완료로 판단한다. 세 분할이 하나의 동일 시각 스냅샷임을 보장하는 것은 아니며, 2단계의 추적 자료로 사용하고 학습 데이터 버전 고정 시 별도로 판단한다.

## 3단계 조사 이력

사용자 승인으로 CANCEL_COMPLETE 1,523행을 정답 수량 제외 대상으로 표시했다. `data/order-items-status-v1.csv`는 원본 42,511행과 전체 값을 보존하고 상태별 판단, 반복 상품항목코드 여부, `training_ready=false`를 붙인 검토용 파일이다. 완료 후보 39,906행, 진행 중 검토 1,029행, 반품/교환 검토 53행이다. 완료 후보도 아직 최종 학습 대상이 아니다. [검증 집계](evidence/status-review-v1.json).

재현: `python3 -m scripts.prepare_status_review data/order-items-v2.csv --output data/order-items-status-v1.csv` (기존 출력 덮어쓰기 금지).

현재 자료로 XGBoost v1을 만든 뒤 과거 이력을 늘리는 버전을 비교하기로 했다. 다른 상태와 정답 이벤트는 아직 미결이며 모델 학습은 실행하지 않았다.

상태 연결 조사에서 42,511행을 42,474개 상품 항목 그룹에 연결했다. 반품/취소와 연결된 완료 행을 개별 승인하지 않도록 그룹 검토 표시를 추가했다. [조사·검증 기록](evidence/lifecycle-review.md). v1 작업 정의는 고객·상품별 다음 재구매 수량이며, 다른 상품 주문을 0 정답으로 넣지 않는다. 아직 모델 학습은 미실행이다.

## 3단계 완료

[v1 계약](purchase-policy-v1.md)에 따라 정상 구매 포함 39,821행, 취소 묶음 제외 1,429행, 보류 1,261행을 판정했다. 취소 완료 1,523행은 보류 묶음에 속한 행까지 모두 정답 기여에서 제외된다. 원본 전체 열·행 및 수량 대사를 확인했고 당시 자동 테스트 11개가 통과했다. [실행 집계](evidence/purchase-policy-v1.json). 이 단계의 산출물은 행 판정이며 일별 이벤트와 정답 쌍은 4단계에서 생성했다.

## 4단계 완료

원본 42,511행을 모두 연결해 정상 구매일 32,492개와 관측된 다음 재구매 정답 쌍 13,587개를 생성했다. 보류로 연결을 끊은 출발 구매 517개, 다음 구매 미관측 18,388개를 별도 보존한다. [실행·검증과 파일 설명](evidence/purchase-events-review.md). 실제 학습과 시점 검증은 미실행이며 다음은 5단계다.

## 추가 업무 범위 점검

사용자가 내부 테스트 주문 제외를 요청했다. 회원코드·주문번호 및 계정 전체/일부 주문 제외 범위는 확인 대기다. 기존 4단계 산출물은 이 제외가 적용되기 전의 버전이며 학습에 바로 사용하지 않는다. 샘플·사은품·개인결제용 상품명, 상품 코드/명칭 변경, 0원 결제·대량 수량을 추가 점검했다. [읽기 전용 집계](evidence/preprocessing-scope-review.json)의 이름 일치는 검토 후보이며 자동 제외 판정이 아니다. 확인된 테스트는 원본을 보존하고 이력·피처·정답·평가 모두에서 제외한 새 버전을 생성한다.

## 충전 상품·테스트 계정 제외 적용

사용자가 만월플러스의 선불 적립금 충전 구조와 테스트 계정 이름을 설명했다. 현재 v3는 충전 상품 6개 코드 594행과 원본에서 확인한 테스트 계정 11행을 제외한다. 테스트는 전부 기존 취소 행이다. 정상 구매일 31,939개, 정답 13,206쌍이며 샘플·사은품 제외는 미적용이다. [검증과 최신 입력](evidence/preprocessing-applied-v3.md).

## 샘플·명시적 사은품 제외 적용, 4단계 완료

샘플 15개와 명시적 사은품 2개 상품코드 제외를 적용했다. 기존 충전 상품·테스트 계정 제외도 유지한다. 현재 입력은 v4이며 정상 구매일 29,473개, 관측 정답 12,920쌍이다. 원본 42,511행 보존, 비제외 이력/정답 동일성, 수량 대사와 새 경로 재생성을 검증했고 자동 테스트 20개가 통과했다. [결과와 재현](evidence/preprocessing-applied-v4.md). 다음은 5단계이며 실제 학습은 미실행이다.

## 5단계 탐색용 입력·분할 생성

고객·상품별 과거 이력 피처와 달력 기준 96/32/32일 단일 분할을 생성했다. 학습 전체 정답 6,579쌍, 검증 1,196쌍, 시험 747쌍이며 내부 조기 종료용 분할도 별도로 보존한다. [현재 계약·한계](feature-split-contract.md), [집계](evidence/features-splits-v1.json). 최종 상태의 과거 가용성 통과는 0개로, 운영 검증용 준비 완료로 표시하지 않는다. 자동 테스트 27개와 실제 이력/경계 대사를 확인했다. 모델과 baseline 점수는 미계산이다.

## 6단계 기준 모델 측정

직전 수량과 개인/상품/전체 간격 중앙값 기준 모델을 적합하고 검증했다. [규칙·실행](baseline-contract.md), [결과·검증](evidence/baseline-v1.md). 검증 1,196쌍의 점수를 기록하고 Grafana에서 확인했다. 테스트 33개가 통과했다. 업무상 날짜·집단 통과 한도와 최종 시험은 미평가이며 다음은 XGBoost 탐색 학습이다.
