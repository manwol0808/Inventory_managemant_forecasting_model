# 전체 이력 확장 실험

2026-09-16 요청 해석: 남은 작업을 순서대로 진행한다. 먼저 2024년 이후 전체 주문 이력을 확보·정제하고, 고정된 검증 기간에서 현재 짧은 이력 모델과 비교한다. 개선 후보를 검증한 뒤 최종 시험과 앱 적용 준비를 진행한다. 실제 고객 장바구니를 수정하는 배포는 이 실험 실행과 구분한다.

## 사전 비교 조건

- 주문 범위: 2024-10-02~2026-09-15. 최신 상태 스냅샷이라는 한계는 유지한다.
- 기존 원본·모델·평가 결과를 덮어쓰지 않는다.
- 같은 상태 판정·샘플·사은품·충전·테스트 계정 제외 원칙을 적용한다. 과거 상품과 계정에서 새 제외 후보를 확인한다.
- 학습 마감 2026-07-13, 내부 조기 종료 경계 2026-06-23, 검증 2026-07-14~2026-08-14, 최종 시험 2026-08-15~2026-09-15를 유지한다. 전체 이력에서는 달력 비율이 6:2:2가 아니다.
- 첫 확장 비교는 기존 21개 피처·XGBoost 설정·수량/날짜 후처리를 유지한다. 검증 정답으로 학습하지 않는다.
- 기존 짧은 이력과 겹치는 원본 구간을 대조한다. 최신 스냅샷 변경이 있으면 데이터 갱신과 이력 확장의 효과를 구분할 수 있도록 짧은 이력 대조군도 같은 스냅샷으로 재생성한다.
- 검증의 고객·상품·출발일과 정답을 대조하고, 공통 평가 대상의 성능을 함께 보고한다. 전체 검증 지표와 공통 대상 지표를 혼동하지 않는다.
- 최종 시험은 개선 후보 선택 동안 잠근다. 업무상 날짜·집단 통과 기준과 운영 시점 상태 가용성은 아직 확정하지 않았다.

## 진행 상태

전체 138,427행을 단일 BigQuery 결과로 확보하고 서버 행 수와 대조했다. 상품번호가 없는 965행과 그 고객의 해당 날짜까지 다른 183행을 별도 보관했다. 식별 불가 구매를 건너뛴 거짓 재구매 연결을 피하기 위한 보수적 처리다. 마지막 식별 불가 날짜는 2025-03-11로 모든 학습/검증 경계보다 앞선다. 정상 식별 가능한 전체 입력은 2024-10-16부터 시작한다. 상품 이름·SKU로 번호를 추정하지 않았다.

동일 최신 스냅샷에서 짧은 이력 대조군과 전체 이력을 생성했다. 학습은 각각 6,579쌍/43,435쌍이며 검증 정답은 동일한 1,196쌍이다. 동일 설정 첫 비교에서 연속 수량 RMSE는 1.6017/1.7244, 날짜 MAE는 5.5594/7.6488이었다. 전체 이력만 늘린 후보는 채택하지 않는다.

## 제한된 개선 실험: 최근 주문 가중치

위 비교 후, 추가 검증 점수를 보기 전에 하나의 후속 후보를 고정한다. 전체 이력·21개 피처·트리 설정·손실·후처리는 유지하고 **학습 가중치만 180일 반감기**로 변경한다. 각 내부 학습/전체 학습 마감일에서 정답 구매일까지의 경과일을 사용해 `2 ** (-age_days / 180)`로 계산한다. 해당 경계 안에 알려진 학습 정답만 사용한다. 내부 조기 종료 평가는 가중하지 않는다. 신규 입력 특성이나 별도 스파이크 모델은 이 실험에 포함하지 않는다.

이는 전체 이력 첫 비교 결과를 보고 설계한 개발 후보다. 검증 결과를 독립적인 최종 성능이라고 주장하지 않는다. 같은 검증을 무제한 재사용하지 않도록 이번 개선은 위 한 후보로 제한한다. 기간·집단별 회귀 여부도 함께 보고한다. 업무 기준이 미정이면 실서비스 자동 반영은 하지 않는다.

## 최종 시험 사전 동결

개선 후보의 검증 수량 RMSE는 1.8185로 최근 이력 대조군보다 나빴다. 검증 주지표가 가장 좋은 `xgboost-short-v2`를 시험 후보로 확정한다. 여기서 후보 선택과 설정 변경을 종료한다. 2026-07-13까지 적합한 저장 모델(수량 90회·간격 124회)을 그대로 쓰고, 검증 자료를 추가해 재학습하지 않는다. 동일한 학습 마감의 `baseline-short-v2`와 이후 2026-08-15~2026-09-15 구간에서 한 번 비교한다.

최종 시험의 고객·상품·출발일/정답 경계와 해시를 확인하고, 모델을 저장 파일에서 읽어 예측한다. 수량은 연속/정수 지표를 모두 보고한다. 날짜 ±7일 비율은 기존의 설명용 지표이며 업무 승인 기준으로 간주하지 않는다. 이 시험을 보고 후보나 설정을 바꾸면 이 구간은 다시 독립적인 최종 시험으로 사용할 수 없으며 새로운 미래 기간이 필요하다.

최종 시험 평가 자체는 이미 요청한 4단계 범위다. 업무 허용 오차와 앱 저장소 확인은 5단계 실제 적용 판단에 필요하다. 평가를 먼저 완료하고 자동 적용의 승인 여부는 별도로 남긴다. 최신 상태 및 관측된 재구매만 평가하는 편향은 최종 시간 구간에도 남아 있으므로 운영 검증이라고 부르지 않는다.
