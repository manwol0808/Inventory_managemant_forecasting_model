# 고객 주기 변화와 품목 속도 실험

2026-09-17 요청 해석: 어제 정제한 데이터에 고객 구매 주기의 변화와 품목별 재구매 속도를 추가하고, 현재 고객 유형에 맞는 모델로 예측한다. 정확한 소진일 적중보다 늦지 않은 장바구니 제안을 우선한다. 신제품은 품목 속도 정보가 충분해질 때까지 해당 통계를 사용하지 않는다.

## 입력과 전처리

`data/purchase-events-full-v1`의 구매 이벤트와 `data/features-splits-full-v1`의 기존 피처를 사용한다. 테스트 계정·충전 상품·샘플·사은품·테스트 상품 제외, 취소·반품·보류 장벽을 적용한 어제의 전체 이력 자료다. 원본이나 기존 정제를 덮어쓰지 않는다. 기존 정상 구매 출발점 90,773건에 피처만 더하고 불규칙·이력 부족 고객을 삭제하지 않는다.

고객 유형은 모든 품목의 고유 구매일로 계산하고, 고객×품목의 주기는 별도 피처로 보존한다. 최근 최대 6개 간격, 최소 4개 간격으로 판정한다. `rebound`는 5개 이상에서 내부 최솟값까지 감소한 뒤 증가하고 양쪽 변화가 중앙값 대비 30% 이상인 경우다. 단조 방향의 변화 비율 75% 이상이며 처음 대비 마지막 간격 변화가 중앙값 대비 30% 이상이면 `speeding_up` 또는 `slowing_down`이다. 나머지 중 변동계수 0.25 이하는 `stable`, 그 밖은 `irregular`, 간격 4개 미만은 `insufficient`다. 반등·추세를 규칙성보다 먼저 판정한다. 이는 이번 실험의 고정 규칙이며 고객의 영구 등급이나 원인을 뜻하지 않는다.

그룹, 최근 간격의 순서, 변화율·변동성, 고객×품목 간격과 품목 통계의 비율을 추가한다. 품목 통계는 그날까지 두 번째 구매가 완료된 최근 100개 간격을 사용한다. 한 날의 이벤트를 모두 반영한 다음 한국 자정에 예측한다. 간격 20건과 서로 다른 구매 고객 5명 조건을 모두 만족해야 품목 간격 중앙값·25분위·변동성·이전 구매 개수당 간격을 활성화한다. 부족하면 빈 값으로 유지하고 `item_speed_available=0`을 기록한다. 지지 표본 수는 표시한다. 기존 상품 ID·구매량 피처까지 지우는 규칙은 아니다. 두 기준은 임시 실험 설정이며 운영 통과 기준이 아니다.

품목 간격은 재구매 속도의 대리 변수다. 실제 소진일·소비량·배송 기간을 측정한 값이 아니며 자주 재구매한 고객이 더 많은 간격을 기여한다. 미래 구매, 정답 간격, 나중에 충족될 표본 수는 현재 피처에 들어가지 않는다. 보류는 해당 고객×품목 이력을 끊고 고객 전체 방문 주기도 보수적으로 초기화한다.

## 고정 비교

[설정](../config/purchase-segments-v1.json)을 실행 전에 고정한다. 기존 입력, 주기 변화 추가, 품목 속도 추가, 조기 예측 목적 추가, 고객군 전문 모델을 차례로 비교한다. 6개 후보는 같은 출발점과 같은 학습 기간을 사용한다. 고객군 전문 모델은 해당 학습 구간에 200건·30고객 이상일 때 학습하며 부족하면 전체 모델로 되돌아간다. 이력 부족은 항상 전체 모델을 사용한다. 저장된 모델의 `SegmentPredictor`는 현재 유형을 조회해 모델을 선택하며 고객 ID 자체를 학습 입력으로 쓰지 않는다.

날짜는 중앙값 목적과 25분위 목적을 비교한다. 후자는 같은 크기의 늦은 오차에 이른 오차보다 3배 비용을 주는 실험 선택이다. 25분위를 사용한다고 실제 보장 확률이 75%가 되는 것은 아니다. 구현은 [XGBoost 3.2 계열의 분위수 회귀](https://xgboost.readthedocs.io/en/release_3.2.0/python/examples/quantile_regression.html)를 따른다. 수량은 같은 자료의 별도 절대오차 모델을 사용한다.

평가는 두 구역을 합치지 않는다.

- 90일 관찰 구역: 기존 4월·5월·6월 개발 구간. 학습 출발점은 학습 마감 90일 이전이고 정답도 마감 이내다. 평가에서 미재구매·보류를 따로 집계한다.
- 챔피언 직접 비교: 기존 검증 1,196건의 동일 ID·정답을 대조한다. 새 후보는 전체 이력에서 7월 13일까지 정답이 관측된 구매를 학습한다. 동결 챔피언은 그 날짜 이후 검증에서만 비교하며 4~6월에 거꾸로 적용하지 않는다. 기간 경계 때문에 짧은 주기가 남는 기존 계약의 한계가 있다. 이미 사용한 검증이며 새 독립 시험이 아니다.

각 예측에 앞당김 없음·7일·10일·예측 간격 25% 최대 7일 정책을 동일하게 적용한다. 모든 제안은 구매 다음 날보다 빠를 수 없다. 늦음·같은 날·1~10일 이른 제안·30일 넘게 이른 제안·구매 다음 날 제안·수량 ±2개·90일 미재구매 대상 제안을 함께 보고한다. 상대 기간 정책은 제품 주기에 따른 앞당김을 비교하기 위한 고정 가설이며 검증된 운영 규칙이 아니다. 결과를 보고 문턱이나 분위수를 바꾸지 않고 챔피언을 자동 교체하지 않는다.

## 실행과 산출물

`.venv/bin/python -m scripts.run_purchase_segments`

출력 `artifacts/purchase-segments-v1/`에는 추가 피처 데이터, 고정 설정, 구간별 모델과 라우터, 예측 CSV, 집계·출처 해시를 저장한다. 기존 경로가 있으면 실행을 거부한다. 실험을 실행한 뒤 [결과](evidence/purchase-segments-v1.md)에 수치와 점검 범위를 기록한다.

최신 상태 스냅샷의 과거 가용성은 여전히 미검증이다. 재구매하지 않은 고객을 날짜 회귀의 0일 정답으로 넣지 않으며, 품절 방지율은 현재 자료로 계산하지 않는다. 앱의 매일 실행·실제 장바구니 쓰기는 이 실험에 포함되지 않는다.
