# 다음 작업 시작점 · 2026-09-16 마감

내일은 **재구매를 너무 일찍 예측하는 문제를 줄이고, 날짜 ±7일 적중을 직접 겨냥하는 실험**부터 시작한다. 사용자가 이 방향에 동의했고 구현·추가 학습은 다음 작업으로 미뤘다. 현재 챔피언은 유지한다.

## 목표와 확정 사항

카페 사장님의 고객×상품별 구매 이력을 추적해서 재구매 시점에 예상 수량을 장바구니에 제안하는 모델이다. 지금은 **주기 ±7일 적중률을 우선**하고 수량 ±2개와 불필요한 추천을 함께 평가한다. 사용자가 원하는 날짜 적중률은 90%이며, 아직 달성하거나 가능성을 입증하지 못했다.

회원 코드를 고객 식별자로 사용한다. 같은 날 여러 상품을 사도 품목별 주기는 따로 추적한다. 고객군을 나누더라도 최종 예측 단위는 고객×상품이다. 수량은 주문 데이터의 개수이며 500g/1kg 같은 옵션 선택은 앱에서 처리한다. 만월 플러스 충전 상품·추천 대상 밖 상품·확인된 테스트 계정은 전처리에서 제외했다. 취소·반품·교환 등 상태를 처리하고 판단 보류 이벤트는 이력 연결을 끊는 정책을 적용했다.

챔피언은 현재 비교 기준으로 지정한 모델이다. 모든 후보 중 최고라고 공통 평가로 입증한 것은 아니다. 기존 점수는 기간 마감까지 재구매가 확인된 사례만의 결과라 짧은 주기가 많이 남을 수 있다. 이후 60일·90일 동안 동일하게 관찰한 실험의 40~50%대 점수와 직접 순위를 매기지 않는다.

챔피언은 규칙적인 반복 구매만 학습하지 않았다. 예측 당시 같은 품목 구매 이력 1회 3,150건, 2회 1,451건, 3~5회 1,485건, 6회 이상 493건을 포함한다. 건수는 고객 수가 아니라 학습 사례 수다.

`predict_replenishment.py`는 `--model`을 생략하면 등록 파일을 읽고 모델·스키마·보고서 해시를 확인한다. 챔피언 등록만으로 재학습하거나 실제 장바구니를 변경하지 않았다.

## 어디까지 완료했나

- 원본 추적, 고객·상품별 정제, 구매일별 이벤트와 다음 구매 정답, 시간순 학습·검증 분할을 구현했다. 무작위로 고객별 6:2:2를 다시 나누지 않는다.
- 확보한 원본 범위는 2024-10-02~2026-09-15이며 식별 가능한 정상 이력의 시작은 2024-10-16이다. 최근 이력뿐 아니라 전체 확보 이력 학습도 이미 비교했다.
- 단순 기준 모델, XGBoost, 최근 이력 가중, 주기 32구성, 생존분석 14구성, 로컬 TabPFN v2와 같은 표본 XGBoost를 비교했다. TabPFN은 구간별 1,000건·두 추정기의 제한 실험이다.
- 고객군별 모델, 품목 구매 이력 2회·4회·6회 이상 평가, 반복 이력만 학습, 11개 인공 시나리오를 비교했다. 인공 자료 점수는 실제 고객 성능의 근거로 쓰지 않는다.
- 규칙적 이력만 골라 주기·수량 모델을 새로 학습했다. 과거 최근 최대 5개 간격, 최소 3개 간격, 모집단 표준편차/평균 ≤0.5를 기준으로 삼았다. 따라서 최소 4회 구매가 필요하고 2~3회는 규칙성 판단을 유보한다.
- 위 실험은 동일한 규칙적 재구매 2,732건에서 날짜 ±7일이 **55.2%→55.9%**, 수량 ±2개가 **98.3%→98.0%**였다. 비교 기준은 90일 실험의 전체 이력 XGBoost이며 챔피언과 다르다. 큰 개선 근거가 없어 챔피언은 유지했다.
- [전체 벤치마크 Grafana](http://127.0.0.1:3008/d/forecasting-benchmarks)를 만들었다. 같은 평가 대상별로 비교하며 규칙적 학습은 05-R 구역에 있다. 48개 패널은 저장된 결과이고 새로고침으로 학습하지 않는다.
- 직전 구현 검증에서 자동 테스트 63개가 통과했다. 규칙적 학습은 저장 모델 30,982개 예측을 재대조했다. 이번 마감 작업은 문서 정리이며 재학습을 실행하지 않았다.

## 고쳐야 할 문제와 아직 모르는 점

1. **예측이 이른 방향으로 빗나간다.** 챔피언 검증 1,196건 중 ±7일 실패는 323건이다. 실제 구매가 예상보다 7일 넘게 늦은 경우가 309건, 빠른 경우가 14건이다. 실패의 절대 오차 중앙값은 11일이다. [집계·원본 해시](evidence/champion-error-diagnosis-v1.json).
2. **불규칙 고객만의 문제가 아니다.** 위 실패 323건 중 과거 규칙적 이력 120건, 변동이 큰 이력 45건, 판단할 이력이 부족한 사례 158건이다. 이는 챔피언의 짧은 이력 범위에서 분류한 결과다. 이력 부족을 불규칙함으로 단정하지 않는다. `10→20→30→10일` 또는 `2→60→2→60일`도 순서가 반복된다면 패턴일 수 있다.
3. **오차 평균과 ±7일 적중률은 다른 목표다.** MAE를 줄이는 현재 학습 방식이 ±7일 적중을 최대화하지는 않는다. 간격의 순서·수량 변화가 추가 신호가 되는지도 검증해야 한다.
4. **구매 기록만으로 수요 변화의 원인을 확정할 수 없다.** 대량 주문, 매출 변화, 휴무, 타 공급처 구매 등은 가능한 설명이며 확인된 원인이 아니다. 필요한 추가 정보는 우선 기존 CSV에서 얻을 수 있는 것부터 시험한다.
5. **재구매하지 않는 대상에도 날짜를 내놓는다.** 재구매한 사례의 날짜 적중률만 높아져도 불필요한 장바구니 추가가 해결되지는 않는다. 확률 문턱을 높이면 놓치는 실제 구매도 증가한다.
6. **평가 독립성과 적용 범위가 남아 있다.** 기존 최종 시험은 이미 사용했다. 현재 실험은 과거 개발 구간을 반복 사용했으며 최신 상태 스냅샷이 당시에도 알려져 있었는지는 미검증이다. 운영 성능은 새 미래 구간의 실제 예측 로그로 확인해야 한다. 2026-09-15 마지막 날의 수집 완전성도 미확인이다.

## 내일 할 순서

1. **고정 ±7일 개선 실험의 비교 조건부터 적는다.** 기존 챔피언은 동결한다. 같은 예측 기준일·대상·관찰 기간에서 후보를 비교하고, 아직 구매하지 않은 사례의 처리도 명시한다. 이미 본 시험 구간을 새 최종 시험으로 부르지 않는다.
2. **가장 먼저 조기 예측 편향 보정을 비교한다.** 기존 예측을 어느 조건에서 얼마나 늦춰야 하는지 과거 개발 구간에서만 학습하고 뒤의 구간에서 확인한다. 실패 사례만 보고 모두 일정 일수 늦추지 않는다. 이력량·상품·과거 주기별 편향을 진단한다.
3. **순서와 수량 정보를 추가한다.** 기존 피처에 이미 있는 직전 간격·최근 수량 통계를 확인한 뒤, 빠진 최근 간격 순서, 간격의 변화, 수량 변화와 간격의 관계를 추가한다. 다음 실제 구매를 보고 고객군이나 피처를 정하지 않는다. 기존 입력과 추가 입력의 차이를 같은 조건으로 비교한다.
4. **±7일 목적에 맞는 확률 예측을 시험한다.** 날짜별 구매 확률에서 예측일 전후 7일의 확률 합이 가장 큰 날짜를 고르는 후보를 만든다. 기존 생존분석을 그대로 다시 돌리는 것이 아니라 평가 목표·날짜 선택 방법의 차이를 명시한다. 주문 후 매일 갱신하는 방식은 최초 1회 예측과 별도 실험으로 관리한다.
5. **전체 성능과 선택 성능을 함께 보고한다.** 날짜 ±7일·±14일, 이른/늦은 오차, 수량 ±2개, 대상 건수·고객 수, 미구매자의 추천 발생을 기록한다. 확신 높은 사례만 선택할 때는 적중률과 전체 대상 중 선택 비율을 함께 보고한다. 선택한 일부에서 90%가 나와도 전체 90%로 표현하지 않는다.
6. **후보를 동결한 뒤 미래 평가로 이어간다.** 개선 후보의 설정·적용 문턱을 고정하고 새 예측 로그를 수집할 계획을 세운다. 앱 연결 시점에는 중복 담기, 사용자가 수정·삭제한 수량, 이미 주문한 상품의 처리도 확정한다.

이 순서는 합의한 다음 작업이다. 편향 보정·추가 피처·±7일 확률 최대화 후보는 아직 구현하거나 학습하지 않았다. 불확실성 구간을 넓혀 얻은 90% 포함률은 고정 ±7일 적중률 90%와 다르다.

## 로컬에서 재개하는 법과 Git 보존 범위

작업 폴더는 `/Users/manwol/Jun/forecastingML`이다. 먼저 `git status --short`로 남은 작업을 확인한다. **이 마감 커밋은 인계 문서, 챔피언 등록 파일, 오류 진단 집계만 보존한다. 기존 구현 코드·실험 문서·대시보드에는 아직 미커밋 작업이 많이 남아 있다.** 초기화·정리 명령으로 지우지 않는다. 전체 구현의 검토·커밋은 별도 남은 작업이다.

원본 CSV, `data/`, `artifacts/`, `.venv/`는 Git 제외 대상이다. 따라서 새로 clone한 저장소만으로는 학습·추론·화면을 재현할 수 없다. 아래 명령은 해당 파일들이 남아 있는 현재 로컬 작업 폴더에서 사용한다. 다른 컴퓨터로 옮기기 전에는 별도 데이터·모델 보존 절차가 필요하다.

| 용도 | 로컬 파일 |
|---|---|
| 챔피언과 짧은 이력 | `artifacts/xgboost-short-v2/`, `data/features-splits-short-v2/` |
| 전체 이력의 이벤트·피처 | `data/purchase-events-full-v1/`, `data/features-splits-full-v1/` |
| 90일 비교 기준 | `artifacts/cadence-groups-full-v1/` |
| 규칙적 학습 결과 | `artifacts/regular-history-v1/`, `docs/evidence/regular-history-v1.md` |
| 반복 구매·TabPFN 결과 | `artifacts/repeat-history-v1/`, `artifacts/tabpfn-repeat-v1/` |
| 전체 작업 및 상세 계약 | `docs/tasks.md`, `docs/app-integration-contract.md` |

저장된 챔피언 파일의 해시를 확인하려면 다음 읽기 전용 명령을 실행한다.

```bash
.venv/bin/python -c 'from scripts.predict_replenishment import champion_path; print(champion_path())'
```

Grafana가 꺼져 있으면 OrbStack/Docker를 켠 뒤 실행한다.

```bash
docker compose -f monitoring/compose.yaml up -d
```

저장 집계로 화면만 재생성하는 명령은 다음과 같다. 기존 학습을 재실행하지 않는다.

```bash
.venv/bin/python -m scripts.build_benchmark_dashboard
```

실험 스크립트는 기존 출력 폴더가 있으면 중단할 수 있다. 기존 `artifacts/`를 삭제하지 말고 새 버전 경로를 정한다. TabPFN과 XGBoost는 기존에 네이티브 충돌이 있어 분리된 프로세스로 실행했다. 노션 작업은 생략하며 추가 학습은 내일 이어간다.
