# 다음 작업 시작점 · 2026-09-17

목표는 **카페의 일요일 밤~월요일 발주에 맞춰 예상 재구매 전에 장바구니를 준비하는 것**이다. 기본은 예상 주의 전주 월요일을 위한 일요일 22시 준비다. 요일 고정으로 여유가 약 7~13일이 될 수 있고, 예정 창이 지난 경우 다음 발주 창이 예측일 전에 가능한지 확인해 기다리거나 즉시 제안한다. [정확한 일정 규칙](app-integration-contract.md). 실제 재구매일 기준 적중률과 예약 동작을 구분한다. 현재 챔피언은 아래 [라우터](#멀티-에이전트-라우터와-챔피언-변경-2026-09-17-후반)다.

## 현재 데이터와 모델

- 전체 DB 추출 범위는 2024-10-02~2026-09-15, 식별 가능한 정제 이력은 2024-10-16~2026-09-15다. 테스트 계정·충전·샘플·사은품·테스트 상품 제외와 보류 장벽을 유지한다. 고객×품목을 예측하며 수량은 옵션의 개수다.
- 라우터의 기본 모델은 `xgboost-short-v2`다(2026-09-16~17 오전 챔피언, [등록 파일](../config/champion.json)의 `base_model`). 학습 이력은 2026-04-09~07-13, 6,579쌍이다. 검증 1,196건의 날짜 ±7일은 73.0%, 이미 사용한 시험 786건은 76.3%다.
- 이번 추가 전처리는 기존 전체 이력 출발점 90,773건을 유지했다. 고객 전체 구매일의 주기 변화와 고객×품목 주기는 별도로 계산한다. 신제품 속도 통계는 과거 20간격·5고객 이상일 때 활성화하는 임시 기준이다.
- 로컬 미리보기는 예측 재구매일 `reorder_on`과 기본 주간 정책의 `cart_at`을 분리한다. `due`는 시각 기준이며 `cart_on`은 날짜 표시용이다. `lead_days` 모드에서 기존 10일 앞당김도 선택할 수 있다. 실제 앱 쓰기·예약 실행은 미구현이다.

## 오늘 완료한 실험

[고객 유형·품목 속도 실험](purchase-segments-v1.md)은 총 8개 후보를 4개 시간 구간에서 학습했다. 최초 6개 뒤 목적함수와 피처 효과를 분리하는 대조 2개를 추가했다. 고객 유형은 불규칙·일정·짧아졌다 길어짐·점점 짧아짐·계속 길어짐·이력 부족으로, 과거 최근 최대 6개 간격에서 매번 다시 판정한다. 전문 모델은 학습 지지 표본이 충분할 때만 사용하고 나머지는 전체 모델로 되돌린다.

[결과와 유형별 수치](evidence/purchase-segments-v1.md): 같은 고객패턴+품목 피처에서 늦음 비용을 3배로 주면 90일 관찰의 늦은 제안이 30.95%→11.95%로 줄지만 30일 초과 조기 제안은 14.67%→21.90%로 늘었다. 고객군 분리나 품목 정보 추가 자체의 효과는 작거나 악화했다. 미재구매 대상에도 날짜를 내놓는 문제가 남았다.

실제 재구매일 10일 전~당일 제안율은 동일 검증 1,196건에서 챔피언 65.64%, 새 통합 조기 모델 64.97%, 전문 조기 모델 65.22%다. 90일 관찰의 통합 조기 모델은 35.12%다. 비교 정책은 예측 간격의 25%·최대 7일 앞당김이며 현재 주간 미리보기 정책과 다르다. 당일 제안은 범위에 포함하되 별도로 보고한다. 두 평가 구역을 합치지 않는다.

관련 테스트 18개, 전체 출발점·직전 간격 대사, 품목 통계 200표본 대조, 저장 예측 재실행과 지표 독립 재계산을 완료했다. [검증 기록](evidence/purchase-segments-verification-v1.json). 고객군별 실제 사례 8개는 `artifacts/purchase-segment-examples-v1/examples.md`에 있고, 실제 BigQuery의 64주문을 조회해 해당 품목 상세·정답과 대조했다. 잘 맞춘 사례만 선택하지 않았다.

## 다음 개선

2026-04-09부터의 짧은 정제 이력에도 동일한 추가 전처리·8개 후보를 적용해 학습했다. [비교·분석](evidence/segment-history-comparison-v1.md). 같은 검증 1,196건에서 10일 범위 적중 최고 65.89%는 챔피언보다 3건 많은 정도이며, 늦음 감소와 과도한 조기 제안 증가의 교환 관계가 남았다. 불규칙형만 전문 모델 최소 표본을 충족했다.

다음은 주간 제안 정책을 실제 앱의 예약 실행과 연결하고 중복 담기·새 주문·사용자 수정 처리를 적용하는 것이다. 아직 앱 저장소/API는 확보하지 않았다. 짧은 주기에 발주 요일을 기다리다 늦어지지 않도록 예외 처리를 유지한다. 군 분리·새 피처가 항상 유리하다고 가정하지 않는다.

실측 소진일·소비량·배송 기간은 현재 주문 자료에 없다. 최신 상태 스냅샷의 과거 가용성도 미검증이다. 이미 사용한 검증·시험을 새 독립 시험으로 부르지 않는다. 운영 성능은 새로운 미래 로그로 확인해야 한다.

## 멀티 에이전트 라우터와 챔피언 변경 (2026-09-17 후반)

- 챔피언은 사용자 요청으로 라우터 `multi-agent-router-v1`(`champion-v2`)이다. 일정형 XGBoost 25분위, 점점 짧아짐 TabPFN 25분위, 나머지는 기본 모델 `xgboost-short-v2`. 첫 구매에는 담지 않고, 에이전트 학습에서 2026-01~02 제외. [구조와 전체 실험 기록](multi-agent-architecture.md), [등록](champion-benchmarks.md).
- 평가 기준(사용자 결정): 전주 월요일 담기 고정, 45일 안 재구매의 날짜 ±7일 적중. 첫 구매 제외 후 월별 90일 평가에서 기존 챔피언 방식 56.4%, 라우터 56.0%. 라우터의 일정형 90.7%는 30일 안 재구매 118건에 한정된 수치다.
- 사용자는 **여기서 모델·규칙을 더 바꾸지 않고 앱 연동으로 넘어가기로 했다.** 연동 시 등록된 라우터와 기본 모델 중 무엇을 쓸지 정해야 한다. 배치 일정은 `python -m scripts.router_champion predict`.
- 검토만 하고 적용하지 않은 것: 구간별 허용 범위 채점, 일정형 짧은 주기의 평소 주기 규칙, 22~30일 고정값(챔피언과 차이 없음), 늦음 감소용 담는 날 앞당김(2~4번째 30%·5번째부터 21일 이상 20%로 늦음 15.0%→7.8%, 15~30일 일찍 26.5%→32.9%).
- 아직 안 한 검수: 한 번도 평가에 쓰지 않은 2026-06-17~07-13 출발 사례 시험, 2026-09-16 일정의 45일 뒤(2026-10-31) 실제 구매 대조.

## 로컬 재개와 보존

먼저 `git status --short`를 확인한다. 코드·설정·테스트·SQL·문서는 Git 보존 범위지만 원본 CSV, `data/`, `artifacts/`, `.venv/`는 제외 대상이다. 새 clone만으로 학습을 재현할 수 없으므로 별도 데이터·모델 보존이 필요하다.

기존 출력 폴더를 삭제하지 않고 새 버전 경로를 사용한다. TabPFN과 XGBoost의 네이티브 충돌 이력이 있어 별도 프로세스를 유지한다. 노션 작업은 생략한다.
