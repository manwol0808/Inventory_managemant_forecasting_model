## 오늘 완료한 실험

[고객 유형·품목 속도 실험](purchase-segments-v1.md)은 총 8개 후보를 4개 시간 구간에서 학습했다. 최초 6개 뒤 목적함수와 피처 효과를 분리하는 대조 2개를 추가했다. 고객 유형은 불규칙·일정·짧아졌다 길어짐·점점 짧아짐·계속 길어짐·이력 부족으로, 과거 최근 최대 6개 간격에서 매번 다시 판정한다. 전문 모델은 학습 지지 표본이 충분할 때만 사용하고 나머지는 전체 모델로 되돌린다.

[결과와 유형별 수치](evidence/purchase-segments-v1.md): 같은 고객패턴+품목 피처에서 늦음 비용을 3배로 주면 90일 관찰의 늦은 제안이 30.95%→11.95%로 줄지만 30일 초과 조기 제안은 14.67%→21.90%로 늘었다. 고객군 분리나 품목 정보 추가 자체의 효과는 작거나 악화했다. 미재구매 대상에도 날짜를 내놓는 문제가 남았다.

실제 재구매일 10일 전~당일 제안율은 동일 검증 1,196건에서 챔피언 65.64%, 새 통합 조기 모델 64.97%, 전문 조기 모델 65.22%다. 90일 관찰의 통합 조기 모델은 35.12%다. 비교 정책은 예측 간격의 25%·최대 7일 앞당김이며 현재 주간 미리보기 정책과 다르다. 당일 제안은 범위에 포함하되 별도로 보고한다. 두 평가 구역을 합치지 않는다.

관련 테스트 18개, 전체 출발점·직전 간격 대사, 품목 통계 200표본 대조, 저장 예측 재실행과 지표 독립 재계산을 완료했다. [검증 기록](evidence/purchase-segments-verification-v1.json). 고객군별 실제 사례 8개는 `artifacts/purchase-segment-examples-v1/examples.md`에 있고, 실제 BigQuery의 64주문을 조회해 해당 품목 상세·정답과 대조했다. 잘 맞춘 사례만 선택하지 않았다.

- 평가 기준(사용자 결정): 전주 월요일 담기 고정, 45일 안 재구매의 날짜 ±7일 적중. 첫 구매 제외 후 월별 90일 평가에서 기존 챔피언 방식 56.4%, 라우터 56.0%. 라우터의 일정형 90.7%는 30일 안 재구매 118건에 한정된 수치다.

- 검토만 하고 적용하지 않은 것: 구간별 허용 범위 채점, 일정형 짧은 주기의 평소 주기 규칙, 22~30일 고정값(챔피언과 차이 없음), 늦음 감소용 담는 날 앞당김(2~4번째 30%·5번째부터 21일 이상 20%로 늦음 15.0%→7.8%, 15~30일 일찍 26.5%→32.9%).
- 아직 안 한 검수: 한 번도 평가에 쓰지 않은 2026-06-17~07-13 출발 사례 시험, 2026-09-16 일정의 45일 뒤(2026-10-31) 실제 구매 대조.

## 앱 연동 시 반드시 먼저 넣을 것 (2026-09-18)

아래 셋은 **연동 시점에 없으면 나중에 붙여도 소용없다.** 이미 한쪽 규칙에 익숙해진 매장이 생기면 비교가 오염된다.

1. **A/B 그룹 배정** — 매장ID 해시로 두 그룹. 현행 규칙과 새 규칙을 동시에 돌려 실측 비교한다. 지금 수치는 전부 과거 재생이며 「사장님 행동이 제안에 영향받지 않는다」는 가정 위에 있다.
2. **영구 홀드아웃 5%** — 끝까지 제안을 보내지 않는 매장군. 자기확증 루프를 막는 유일한 장치다. 우리가 담은 것이 구매를 앞당기면 그 구매가 다시 학습 데이터가 되고, 모델은 자기 예측이 맞았다고 학습한다. 홀드아웃이 자연 상태의 구매 주기를 계속 알려주는 기준선이 된다. A/B와 별개로 상시 유지한다.
3. **`cart_suggested`에 모델 버전·그룹 기록** — 나중에 조인할 키다.

### 앱이 쏴줘야 하는 이벤트

공통 필드는 매장ID, 품목ID, 시각(KST)이다. 매장ID는 주문 DB와 같은 키여야 조인된다.

| 이벤트 | 추가 필드 | 답해주는 것 |
|---|---|---|
| `cart_suggested` | 담은 수량, 예측 재구매일, 모델 버전, A/B 그룹 | 기준점. 없으면 나머지 해석 불가 |
| `cart_item_removed` | 지운 시각, 되돌리기 여부 | **최우선.** 과도 조기의 실제 비용. 늦음 대 조기 교환비를 정하는 유일한 근거 |
| `cart_quantity_edited` | 이전/이후 수량 | 수량 모델의 진짜 오차 |
| `cart_checkout` | 주문ID, 품목별 **출처 표시**(우리 제안 / 직접 담기) | 주문 DB엔 주문만 있고 우리 제안이었는지 연결이 없다. 실측 적중률의 전제 |
| `cart_item_added_manually` | — | 우리가 놓친 품목. 재현율 실측 |
| `cart_viewed` | 그때 담긴 품목 수 | 장바구니가 몇 개 넘으면 안 보나 |

앱이 아닌 커머스/주문 DB 쪽에서 추가로 필요한 것: **품절·미입고**(지금은 간격 증가를 전부 수요 변화로 오인한다), **배송 도착일**(주문일 ≠ 소진 시작일), **매장 휴무·영업일**. 취소·반품·보류는 `scripts/build_purchase_events.py`가 이미 처리하므로 추가 불필요하다.

규모는 부담이 아니다. 매장 7,792개, 고객×품목 짝 31,333개, 담기 제안 연 29,356건(하루 80건)이다. 짝별 보정 상태는 2~3MB로 `data/tracking-v1.sqlite`에 붙이면 된다.

## 연동 후 할 일 (2026-09-18)

1. **A/B로 챔피언 판정** — 수량·늦음은 약 2주, 21일 안 적중은 약 6주면 유의한 차이가 나온다(유의수준 5%, 검정력 80%, 그룹당 월 1,220건 기준). 참고로 차이가 ±0.2%p인 규칙 변형은 A/B로도 판별 불가능하다.
2. **재예측 재시도** — [현재 실패](reorder-champion-v1.md)의 원인은 피처가 전부 구매 시점 고정값이라 구매와 구매 사이에 새 정보가 도착하지 않는다는 것이었다. `cart_viewed`·`cart_item_removed`는 정확히 그 사이에 도착한다. 실패한 실험을 그대로 다시 돌린다.
3. **짝별 보정 확장** — 지금은 늦음 신호 하나로만 돌아 −1.1%p에서 천장이다(이력이 무한히 쌓여도 비슷하다). 삭제·수정·열람 네 신호로 넓힌다. 구현은 `scripts/pair_adjustments.py`에 있다.
4. **매장 활동량별 성능 분리** — 매장당 연간 제안이 중앙 3건, p90 21건, 최대 325건이다. 전체 평균 62%가 소수 활성 매장에 끌려 올라간 값일 수 있다. 매장별로 쪼개 본다.
5. **건태 매니저께 요청** — 매장 주문 리듬 모델의 원시 신호(GA 방문·담기, 쿠폰, 적립금)를 **2025-07~2026-06 구간**으로 다시 뽑아달라고 한다. 현재 받은 `push_valid_test.csv`는 2026-07~09라 우리 검증 기간과 겹치는 날이 0일이다. 지금은 워크포워드 예측 날짜 하나만 피처로 썼고 그것이 gain 4위였다.

### 하지 않아도 되는 것 (측정 완료)

- **담는 날 규칙 탐색** — 25가지를 시험했다. 균일/비례 앞당김, 주기 하한, 월요일 스냅 변형, 예측 보정표, 구간별 오프셋, 구매 후 고정일 담기, 계층 규칙, 예측 버킷별 완전탐색. 예측 간격만 입력으로 쓰는 규칙의 상한이 현행 대비 +0.2%p다.
- **표본 증량** — 학습 1개월 1,936건과 6개월 10,082건의 성능이 같다. 학습곡선이 평평하고 오래된 데이터를 넣으면 오히려 조금 나빠진다.
- **라우터 구조 재학습** — 21일 안 적중이 사실상 동일하다. 학습 표본이 `stable` 1,076건, `speeding_up` 250건뿐이라 전용 모델이 붙는 것은 전체의 7%다.
- **간격 예측 모델 교체** — 다섯 가지를 월별 워크포워드로 시험해 모두 기각했다. 분위 0.7(늦음 9.5%→19.3%), enriched 64피처 교체(12폴드 61.9%→61.6%), 학습 창 365/730/1100일(동일), 학습 모집단 제한(58.6%→56.8%), 매장 리듬을 피처로 투입(±0.3%p, 부호 불안정). 기각한 코드는 남기지 않았다. **단일 검증셋으로 판단하면 안 된다** — 소진된 1,196건 코호트의 ±7일 대칭 지표는 분위 0.7을 개선으로 표시했지만 실제로는 늦음을 두 배로 만든다.
